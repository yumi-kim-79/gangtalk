# 배너 슬라이더 옆 슬라이드 미리보임 (peek) — 진단

날짜: 2026-07-02
증상: PR #130 배포 후 배너 자동 넘김 정상. 단 **현재 배너 옆으로 이전/다음 배너가 일부 미리 보임**. StoreFinder/PartnersPage 배너 동일
범위: 진단 전용. 코드 / CSS / PR / 배포 변경 0건.

---

## 0. TL;DR

- **원인 = 배너 부모 컨테이너에 `overflow: hidden` 이 없음**
  - `.sf-banners` (`StoreFinder.vue:1944-1947`) — overflow 명시 없음 → default `visible`
  - `.pp-banners` (`PartnersPage.vue:1392-1395`) — 동일
- PR #130 이 안에 넣은 flex track (`display:flex; width:100%; translateX(-N%)`) + 각 article `flex: 0 0 100%` 는 **정상 계산**
  - track width = 부모 폭 100% = ~380px
  - article 3 개 × 100% = 총 폭 300% (nowrap → 밖으로 나감)
  - translateX(-100%) = 정확히 한 슬라이드 이동
- **문제**: article 이 track 밖으로 나갔을 때 이를 **자르는 상위 컨테이너가 없음** → 좌우로 노출됨
- PR #130 이전 (`slice(-1) / slice(0,1)` 로 1장만 렌더) 에는 자식이 1개라 밖으로 나올 게 없어 문제 안 보였음
- **gap / padding / minus margin 은 문제 아님**. `.banners { display:flex; flex-direction:column; gap }` 은 세로 방향이라 track 배치와 무관
- **rs-scroller 의 `--cards-per-view: 2.5` 는 완전 별개** (Top5 카드 스크롤) — 배너와 무관
- **최소 fix**: track wrapper inline style 에 **`overflow: hidden` 한 줄** 추가 (CSS 파일 무변경)

## 1. PR #130 이 넣은 슬라이더 구조 확인

### 1-1. StoreFinder (`StoreFinder.vue:82-122`)
```html
<section class="banners sf-banners" v-if="allBanners.length">
  <div :style="{
    display: 'flex',
    width: '100%',
    transform: `translateX(-${slideIdx * 100}%)`,
    transition: 'transform 0.5s ease',
  }">                                       <!-- ← track wrapper (inline) -->
    <article
      v-for="(b, i) in allBanners"
      class="banner"
      :style="{ flex: '0 0 100%', minWidth: '0' }"   <!-- ← 각 배너 (inline) -->
    >
      <img class="banner-img" ... />
    </article>
  </div>
  <div class="sf-banner-dots" v-if="allBanners.length > 1">...</div>
</section>
```

### 1-2. PartnersPage (`PartnersPage.vue:40-76`)
- **완전히 동일 구조** (클래스명만 다름)

### 1-3. 이동량 계산 검증
| 항목 | 값 |
|---|---|
| track width | `100%` (inline) = 부모 (`.sf-banners`) 폭 |
| article flex | `0 0 100%` (inline) = flex-basis: 100% of track = 부모 폭 |
| translateX | `-${slideIdx * 100}%` = track 자체의 -100% = -부모 폭 |
| **article 폭 = 이동량** | ✓ **정확히 1장씩 이동** |

→ **translateX 계산 자체는 정확**. gap 이나 padding 으로 인한 어긋남 없음.

## 2. 옆으로 미리 보이는 정확한 원인

### 2-1. 부모 컨테이너의 `overflow` 확인

**StoreFinder `.sf-banners` (`:1944-1947`)**:
```css
.sf-banners{
  position: relative;
  margin: 0 0 8px;
  /* overflow 명시 없음 → default: visible */
}
```

**StoreFinder `.banners` (`:2273`, 부모 클래스도 상속)**:
```css
.banners{
  display: flex;
  flex-direction: column;      /* ← 세로 flex (배너 여러 장이 세로로 나열되던 옛 구조) */
  gap: 8px;
  margin: 4px 0 6px;
  /* overflow 명시 없음 */
}
```

**PartnersPage `.pp-banners` (`:1392-1395`)**:
```css
.pp-banners{
  position: relative;
  margin: 0 0 12px;
  /* overflow 명시 없음 */
}
```

**PartnersPage `.banners` (`:1597-1602`)**:
```css
.banners{
  display: flex;
  flex-direction: column;
  gap: 10px;
  margin: 4px 0 12px;
  /* overflow 명시 없음 */
}
```

→ **두 페이지 모두 배너 부모 컨테이너에 `overflow: hidden` 이 없음**

### 2-2. 문제 발생 메커니즘
```
.sf-banners (overflow: visible, 부모 폭 380)
  └── track wrapper (display:flex; width:100%; translateX(-N%))
      ├── article 1 (flex:0 0 100% = 380px)     ← 화면 안 (idx=0 일 때)
      ├── article 2 (flex:0 0 100% = 380px)     ← 오른쪽 밖 (380~760px)
      └── article 3 (flex:0 0 100% = 380px)     ← 더 오른쪽 밖 (760~1140px)
```
- article 3 개가 flex nowrap 으로 track 밖으로 나감
- track 도 width:100% = 380 유지 (자식이 밖으로 나가도 track 자체 폭은 유지)
- **`.sf-banners` overflow:visible → track 이 밖으로 나간 것도 그대로 표시**
- 결과: 다음/이전 배너가 좌우로 삐져나와 보임 (peek 현상)

### 2-3. PR #130 이전 (slice(-1)) 에는 왜 안 보였나?
- `oneBanner = withImg.slice(-1)` — 1장만 렌더
- v-for="oneBanner" → article 1 개
- article 1 개 × 100% = 100% = 부모 폭 정확히 맞음 → 밖으로 나갈 게 없음 → overflow 문제 발현 안 함

### 2-4. `.banner` 자체 `overflow: hidden` 은 왜 도움 안 되나
**StoreFinder `.banner` (`:2274`)**:
```css
.banner{ position:relative; overflow:hidden; border-radius:16px; ... }
```
- 이 `overflow: hidden` 은 **article 안 (이미지 등 자식) 을 자름**
- article 자체가 부모 밖으로 나가는 것을 막지는 못함
- 밖으로 나간 article 자체는 여전히 화면에 표시됨

## 3. 다른 가능한 원인 배제

### 3-1. gap 배제
- 부모 `.banners { gap: 8px/10px }` 은 **flex-direction: column** 축 (세로) → 자식이 하나 (track wrapper) 이거나 track + dots 사이 세로 gap 만 적용 → 가로 배치와 무관
- track wrapper 자체 inline style 에 gap 없음

### 3-2. padding 배제
- `.sf-banners / .pp-banners` padding 없음
- `.banner` padding 0 (`:2274`)
- track wrapper 도 padding 없음

### 3-3. minus margin 배제
- `.banners margin: 4px 0 6px` — 세로만
- `.banner` margin 없음

### 3-4. rs-scroller (`--cards-per-view: 2.5`) 배제
- **Top5 카드 스크롤 전용** (`.rs-scroller`, `PartnersPage.vue:1795-1798`)
- `.rs-card width: calc(... / 2.5); flex: 0 0 auto`
- 배너 (`.pp-banners`) 와 완전 별개 클래스 → 배너에 영향 0
- `--cards-per-view` custom property 는 rs-scroller scope 안에서만 정의

### 3-5. translateX 계산 배제 (§1-3 검증 완료)
- 정확히 100% 씩 이동. gap 어긋남 없음

→ **원인은 부모 컨테이너 `overflow: hidden` 부재 하나**

## 4. 최소 수정 방법

### 4-1. 옵션 A — track wrapper inline style 에 `overflow: hidden` 추가 (★ 권장, CSS 무변경)

**변경 대상**:
- `src/views/StoreFinder.vue:83-89`
- `src/pages/PartnersPage.vue:41-47`

**변경 내용**:
```diff
  <div
    :style="{
      display: 'flex',
      width: '100%',
+     overflow: 'hidden',
      transform: `translateX(-${slideIdx * 100}%)`,
      transition: 'transform 0.5s ease',
    }"
    @touchstart.passive="onSliderTouchStart"
    @touchend.passive="onSliderTouchEnd"
  >
```

**효과**:
- track wrapper 자체가 `overflow: hidden` 을 가짐
- flex 자식 (article 3개) 이 밖으로 나가는 것은 유지 (flex nowrap 그대로) 하지만 밖으로 나간 부분은 시각적으로 잘림
- **정확히 1장만 화면에 보임**
- **CSS 파일 무변경** (PR #130 정책 유지)
- **translateX 이동 정상** (자식은 여전히 밖에 있어 좌우 이동 가능)

**주의점**:
- `overflow: hidden` 이 transform 자식에 적용될 때 브라우저마다 처리 살짝 다를 수 있음. 특히 `will-change: transform` 없으면 layer 승격 안 되어 자식 이동 시 자름이 자연스러움
- 이 케이스는 자식이 밖에 있고 안 보이면 됨 → hidden 정상 동작

### 4-2. 옵션 B — 부모 컨테이너 CSS 에 `overflow: hidden` 추가 (CSS 변경)

**변경 대상**:
- `src/views/StoreFinder.vue:1944-1947` (`.sf-banners`)
- `src/pages/PartnersPage.vue:1392-1395` (`.pp-banners`)

**변경 내용**:
```diff
  .sf-banners{
    position: relative;
    margin: 0 0 8px;
+   overflow: hidden;
+   border-radius: 16px;   /* 자식 .banner 의 radius 와 통일 */
  }
```

**효과**:
- 부모 자체가 자름
- **CSS 파일 변경 필요** — 사용자 명세 "CSS 안 건드림" 정책 위반 가능성
- radius 을 부모로 옮겨야 자연스러움 (자식은 `overflow:hidden` 안에서 잘림)

### 4-3. 옵션 C — 마크업에 새 wrapper 추가

**변경**: 기존 track wrapper 를 새 wrapper 로 감쌈
```html
<div :style="{ overflow: 'hidden', width: '100%' }">
  <div :style="{ display: 'flex', ... }">
    ...
  </div>
</div>
```

- 마크업 계층 추가
- overflow 는 새 wrapper 가 담당, 이동은 안쪽 track 이 담당
- 관심사 분리는 명확하지만 마크업 계층 늘어남
- **옵션 A 로 충분** — 굳이 계층 추가 안 해도 됨

### 4-4. 권장

**옵션 A** (track wrapper inline `overflow: hidden` 한 줄)
- 최소 변경 (2 파일 × 1줄)
- CSS 파일 무변경 (PR #130 정책 유지)
- 마크업 계층 유지

## 6. 결론

- **peek 원인** = **부모 배너 컨테이너 (`.sf-banners / .pp-banners`) 에 `overflow: hidden` 없음**
- PR #130 은 track/article/translateX 계산은 완벽. 부모 컨테이너 clip 이 없어서 flex 자식이 밖으로 나간 상태 그대로 표시
- **gap / padding / minus margin / rs-scroller 은 원인 아님**
- **최소 fix** = track wrapper inline style 에 `overflow: hidden` 한 줄 추가 (2 파일 × 1줄, CSS 파일 무변경)
- **본 문서는 진단만**. 코드/CSS/PR/배포 없음
