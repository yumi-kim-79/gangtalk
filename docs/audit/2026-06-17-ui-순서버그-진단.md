## 증상 1: AuthPage 의 "인증번호 발송" 버튼이 화면에 안 보임

### 사실
- 마크업은 **항상 렌더링됨** (`v-if` / `v-show` 조건 없음)
  - `src/pages/AuthPage.vue:186-193`
  ```vue
  <button type="button" class="btn sm ghost" @click="sendSmsCode" :disabled="sendingSms">
    {{ sendingSms ? '발송중…' : '인증번호 발송' }}
  </button>
  ```
- 회원가입 클릭 시 알림은 정상:
  - `src/pages/AuthPage.vue:592-595` — `if (!smsVerified.value) alert('휴대폰 인증을 완료해야 회원가입이 가능합니다.')`
  - 즉, **버튼이 DOM 에는 있지만 사용자가 못 본다 → 클릭 안 함 → `smsVerified` 영원히 false** 의 시나리오

### 원인 추정 — 증상 2 와 **같은 뿌리** (CSS 대비 부족)
- `src/pages/AuthPage.vue:809-823` `.auth-page .btn.sm`:
  ```css
  border: 1px solid var(--line) !important;   /* #eaeaea — 거의 안 보임 */
  background: var(--surface) !important;       /* #ffffff — 페이지 배경과 동일 */
  /* color 미지정 → 브라우저 기본 (대부분 회색) */
  ```
- `src/styles/theme.css:8-13` (라이트):
  ```css
  --bg: #ffffff;
  --surface: #ffffff;   /* ← --bg 와 동일 */
  --line: #eaeaea;
  ```
- 결과: **흰 배경에 흰 버튼 + 옅은 보더 + 회색 텍스트** → 사실상 투명
- "ghost" 클래스는 코드 내에 별도 정의 없음 → 추가 효과 0

### 보조 검토: App Check / 에러가 버튼 표시에 영향?
- `sendSmsCode` 호출부 (`AuthPage.vue:318-351`) 는 단순 `httpsCallable` 호출. **App Check 토큰은 Firebase SDK 가 자동 첨부** (회원 빌드는 IS_ADMIN_BUILD=false 라 reCAPTCHA Enterprise 활성)
- **버튼 표시 자체는 호출 결과와 무관** (그냥 항상 보임). 즉 버튼 안 보이는 건 100% CSS 문제

### 고칠 방향
- `AuthPage.vue:809-823` `.btn.sm` 에 명시적 컬러 추가:
  - **배경**: `var(--accent-weak)` (`#ffd1e6` 핑크) 또는 흰색 + 핑크 보더 (`border: 1.5px solid var(--accent)`)
  - **색**: `var(--accent)` (`#ff2d8d`) 또는 진한 회색
  - **다크모드** 분기 (`[data-theme="black"]` 룰) 도 함께 추가
- 또는 더 근본적으로: `theme.css` 에서 `--surface` 를 `#f7f7fa` 정도 옅은 회색으로 변경 (전역 대비 확보) — 단 영향 범위 큼

## 증상 2: 로그인/회원가입 탭 + 입력칸 옆 버튼 회색으로 안 보임

### 사실
- 탭은 `:766-773` 에서 핑크로 명시:
  ```css
  html[data-theme='white'] .auth-page .tabs .tab.active {
    background: #ff2c8a !important;
    color: #fff !important;
  }
  html[data-theme='white'] .auth-page .tabs .tab:not(.active) {
    color: #ff6aa8 !important;
    border-color: #ffd0e3 !important;
    background: transparent !important;
  }
  ```
- **활성 탭은 핑크, 비활성 탭은 분홍 글씨로 보임** — 명시 색이 있음
- 그런데 **`.btn.sm` (중복확인/인증번호 발송/인증확인 버튼) 은 명시 색 없음** (`:810-823`)
- 마찬가지로 `.btn.primary.xl` (회원가입 큰 버튼) 은 명시 색 (`:765-781` 핑크 그라디언트) 있음

### 원인 추정
- **탭은 의도대로 핑크로 보임** (사용자가 "회색"이라고 한 건 비활성 탭의 분홍이 너무 옅어서일 가능성)
- **진짜 회색으로 안 보이는 건 `.btn.sm`** (중복확인/인증번호 발송/인증확인) — 증상 1 과 완전히 동일 원인
- `--surface` (#ffffff) = `--bg` (#ffffff) 충돌
- CSS 변수 자체가 라이트 모드에서 표면/배경을 분리 안 함

### 다크모드 확인
- `theme.css:39-55` 다크 분기에서는 `--bg:#0f1013`, `--surface:#15161a` 로 **다름** → 다크모드에서는 대비 OK
- 즉 **라이트 모드 한정 버그**

### 고칠 방향
- 옵션 A (좁은 수정): `.btn.sm` 의 `background` 를 `var(--accent-weak)` 또는 흰색 + 핑크 보더로 변경
- 옵션 B (전역 수정): `theme.css:13` 의 `--surface` 를 `#f8f8fb` 정도로 변경
  - 영향: 다른 페이지의 카드/입력 배경도 약간 회색 톤이 됨 → 사용자 페이지 전체 톤 검토 필요
- 옵션 C (탭 색상 강화): 비활성 탭 색을 `#ff2c8a` (진한 핑크) 로 올려 대비 ↑

권장: **옵션 A 우선** (좁고 안전). 검증 후 필요하면 B/C 검토.

#### 🟢 후보 #4: SortableJS DOM revert 패턴의 race
- `StoresManagePage:onEnd` / `Top5ManagePage:onEnd` / `BannersManagePage:onEnd`:
  ```js
  const list = evt.from
  list.insertBefore(evt.item, list.children[oldIndex])
  reorderXxx(oldIndex, newIndex)
  ```
- SortableJS 가 옮긴 DOM 을 우리가 되돌린 뒤 reactive state 만 변경하는 패턴
- `reorderApproved/reorderTopRanks/reorderBanners` 의 `displayIds.map(s => s.id)` 가 **Vue 가 아직 재렌더 안 한 시점의 orderedApproved** 를 읽음
- 정상 동작 시 문제 없음 (state 가 즉시 갱신되고 다음 tick 에 재렌더). 그러나 모바일 SortableJS 가 touch 이벤트 종료를 다르게 처리하면 race 가능
- **확인 방법**: PC 와 모바일 둘 다 재현되는지

#### 🟢 후보 #5: 캐시 (브라우저/CDN)
- 사용자 페이지가 stale 번들을 캐시. `vite.config.js` 의 해시 파일명 + `firebase.json` 의 `html no-cache` 헤더는 정상 설정돼 있어 가능성 낮음

- **확인 방법**: 사용자 브라우저 강제 새로고침 (Cmd+Shift+R) 후 재현되는지
