### 3-2. PartnersPage 의 Top5 현재 상태

`src/pages/PartnersPage.vue:1250-1257`:
```
const topByCat = (k) => (
  partners.value
    .filter(p => p.category === k)
    .filter(p => region === 'all' || normRegion(p.region) === region)
    .sort((a,b) => score(b) - score(a))   // ← 자동 정렬
    .slice(0, 5)
)
```
- `score(p) = rating*100 + tags.length*3` (`:897, 1255`)
- 마크업 `:161` — `v-for="(p, idx) in topByCat(sec.key)"`
- **즉 Top5 카드는 이미 카테고리별로 뿌리고 있으나, 관리자가 수동 순서 지정 불가**

### 3-3. 작업 범위 — `partnerTopRanks` 신규 키 + UI 신규

**관리자 측 — 신규 페이지 또는 PartnersManagePage 탭**:
- 카테고리 탭 (PartnersManagePage 의 `partnerCategoryOptions` 8 개 사용)
- 카테고리별 partners 검색 → 추가 → 드래그 정렬 → 저장

```
function topFromRanksP(catKey) {
  const ids = partnerTopRanks.value?.[catKey] || []
  if (!ids.length) return topByCat(catKey)   // ← 폴백: 자동 score
  return ids.map(id => partnersById[id]).filter(Boolean)
                                  .filter(p => 지역/카테고리/기간 통과)
                                  .slice(0, 5)
}
```
- `partnerTopRanks` 빈 카테고리는 기존 auto-score 로 폴백 → 점진 도입 안전

## 4. 카테고리 키 불일치 — 사전 정리 필요 🚨

| 위치 | 카테고리 키 |
|---|---|
| 관리자 (PartnersManagePage `:223-232`) | `salon, nail, ps, real, rental, fit, cafe, etc` (8) |
| 사용자 (PartnersPage `:609-620`) | `ps, skin, beauty, nail, real, fit, deal, shop, etc` (9) |

차이:
- 관리자 `salon` ↔ 사용자 `beauty` (PartnersPage `normCat:640` 가 `salon → beauty` 매핑)
- 관리자 `rental` / `cafe` ↔ 사용자에 없음 → `etc` 폴백
- 사용자 `skin / deal / shop` ↔ 관리자에 없음 → admin 에서 추가 불가

**영향**:
- 순서 변경 (`partnerOrder`): 키 무관, 단일 배열 → 영향 0
- 노출 기간 (`adStart/adEnd`): 카테고리 키 무관 → 영향 0
- **Top5 (`partnerTopRanks`)**: 키 단위로 분기 → **불일치 그대로 두면 admin 에서 `deal` Top5 등록 불가, 사용자 화면에 `skin` Top5 노출 안 됨**

**권장 조치 (Top5 PR 전 별도 PR)**:
1. 카테고리 키 세트 단일화 — 두 페이지가 같은 9-10 개 키 공유. PartnersManagePage 의 `partnerCategoryOptions` 를 PartnersPage 와 동일 키로 확장 (salon 폐기 + beauty/skin/deal/shop 추가)
2. 기존 partners 데이터 마이그레이션 — `salon` 으로 저장된 row 들을 `beauty` 로 옮기는 1회성 스크립트 또는 `normCat` 로 fly-time 변환
3. 마이그레이션 완료 후 Top5 PR 진행

이 정리 없이 Top5 PR 만 들어가면 운영 중 혼선 큼.
