# 신규 등록 시 대표 이미지 업로드 실패 진단

작성일: 2026-06-18
대상 PR: #93 (업체 자가 신규 업소 등록 모드)
산출물 종류: **진단 문서 1개** (코드/룰 수정·PR·배포 없음)

---

## 1. 증상 요약

- 업체 로그인 후 `/biz/my-store` → "신규 등록" 모드 진입
- 업소명/연락처/주소/카테고리 등 텍스트 필드는 모두 정상 입력
- **대표 이미지 첨부 버튼만** 클릭 시 `alert("가게가 선택되지 않았습니다.")` 노출
- 콘솔 추가 노이즈: `BizAccounts users subscribe error: Missing or insufficient permissions`
- 콘솔 정상 로그: `createBizAccount ok` (이전 admin 작업에서 출력된 것으로 추정)

## 2. 정확한 원인 — 2중 차단

### 2-1. 1차 차단 (클라이언트 가드, 즉시 alert)

**위치**: `src/pages/admin/BizMyStorePage.vue:321-328` + `:350-357`

```js
function triggerFilePick() {
  if (uploading.value) return
  if (!currentStore.value?.id) {
    alert('가게가 선택되지 않았습니다.')   // ← 여기서 alert 발화
    return
  }
  try { fileInputRef.value?.click() } catch {}
}

async function onPickImage(e) {
  const file = (e.target.files || [])[0]
  if (!file) return
  const storeId = currentStore.value?.id
  if (!storeId) {
    alert('가게가 선택되지 않았습니다.')   // ← 동일 가드
    return
  }
  ...
}
```

`currentStore` 는 `selectedStoreId` 로부터 파생되는 computed.
**신규 등록 모드** (`creating.value = true`) 진입 시 `startCreate()` 가
`selectedStoreId.value = ''` 로 초기화 → `currentStore.value === null`
→ `currentStore.value?.id === undefined` → `!undefined === true` → alert.

**확정**: 사용자가 본 alert 의 직접적인 원인은 이 분기.

### 2-2. 2차 차단 (Storage Rules, 클라 가드 우회해도 막힘)

**위치**: `storage.rules:29-33` + `:45-52`

```
function isStoreOwner(storeId) {
  return signedIn()
    && firestore.exists(/databases/(default)/documents/stores/$(storeId))
    && firestore.get(.../stores/$(storeId)).data.ownerId == request.auth.uid;
}

match /stores/{storeId}/{allPaths=**} {
  allow read: if true;
  allow write: if (isAdmin() || isStoreOwner(storeId)) && isImage() && sizeOk();
}
```

**핵심**: `isStoreOwner(storeId)` 의 첫 단계 `firestore.exists(stores/{storeId})`
→ 신규 등록 모드에서는 stores doc 자체가 아직 없음 → `exists=false`
→ 권한 거부.

만약 클라이언트에서 가드를 풀고 임시 ID 로 업로드를 시도해도,
**Storage Rule 이 stores doc 의 존재를 확인하므로 마찬가지로 차단됨**.

**결론**: 단순히 클라이언트 가드를 푸는 것으로는 해결 불가.
**stores doc 이 먼저 생성돼야 업로드가 통과한다**.

## 3. 고칠 방향

### 방법 A (권장) — "등록 신청" 먼저, 이미지는 그 다음

흐름:
1. 신규 등록 화면에서 텍스트 필드만 입력
2. "등록 신청" 버튼 클릭 → `createNewStore()` (이미 PR #93 에 구현) 실행
   - `setDoc(stores/{newId}, { ownerId, applyStatus:'pending', approved:false, exposure.gangtalk:false, ... })`
3. 등록 성공 → `creating=false`, `selectedStoreId=newId`,
   기존 "정보 수정" 흐름으로 전환
4. 이 시점부터 `currentStore.value` 가 존재 → 이미지 버튼 alert 해제,
   storage rule 의 `firestore.exists/get` 통과 → 업로드 성공

UX 안내:
- 신규 등록 모드의 이미지 영역에 "등록 신청 후 첨부 가능" 안내 + 버튼 비활성화
- 등록 성공 alert 에 "대표 이미지는 아래에서 첨부해 주세요" 한 줄 추가

장점:
- `storage.rules` / `firestore.rules` 변경 0 — 보안 유지
- 이미 PR #93 의 `createNewStore()` 가 `creating=false; selectedStoreId=newId`
  로 자동 전환되므로 별도 라우팅 불필요
- 코드 변경 최소 (alert 안내 문구 교체 + 이미지 버튼 disabled 조건 추가)

단점:
- 사용자가 한 번에 모든 필드를 채우고 싶어도 2 단계로 분리됨

### 방법 B — Auto-ID 선생성 (단독으로는 불가)

`doc(collection('stores')).id` 를 미리 발급하고 그 ID 로 업로드 시도.

- 클라 가드는 풀 수 있지만 **storage rule `isStoreOwner` 가 firestore doc
  존재를 확인하므로 여전히 차단**.
- 통과하려면 `storage.rules` 의 `isStoreOwner` 를 약화해야 함
  (예: `path` 가 `stores/{auth.uid 가 ownerId 인 storeId}` 인지 검사하지
  말고 단순히 인증만 확인 → **모든 인증 사용자가 임의 stores/*/* 에 쓰기 가능**
  → 보안 큰 손상).
- ❌ 채택 비권장.

### 방법 C — 임시 업로드 경로 + 등록 후 이동

`uploads/{uid}/temp-{ts}.jpg` 같은 별도 경로에 먼저 올리고,
`createNewStore()` 안에서 `stores/{newId}/thumb.jpg` 로 copy 후 임시 파일 삭제.

- `storage.rules` 에 `uploads/{uid}/**` 본인 쓰기 규칙 추가 필요.
- copy/delete 추가 로직 + Cloud Function 또는 클라 다중 단계.
- 1 단계로 보이지만 내부 복잡도 큼.
- 방법 A 의 UX 손해가 견디기 어려운 경우에만 검토.

**권장**: **방법 A**. PR #93 골격을 유지한 채 alert 문구/버튼 disabled 조건만
추가하면 됨. `storage.rules` 무변경, 보안 그대로.

## 4. `BizAccounts users subscribe error` 는 별개 문제

- 발생 위치: `src/pages/admin/BizAccountsPage.vue:189-208` (onSnapshot error 콜백)
- 발화 메시지: "권한 부족: 관리자 계정으로 users 컬렉션을 list 할 수 없습니다 (Firestore rules)"
- 대상 컬렉션: **users** (Firestore) — 본 이미지 버그가 다루는 **Storage `stores/{id}/*`** 과 무관

`firestore.rules:67-70`:
```
match /users/{uid} {
  allow read: if isOwner(uid) || isAdmin();
  ...
}
```

→ `isAdmin()` 은 `admins/{auth.uid}` 문서의 존재 여부로 판별. 콘솔에서
`Missing or insufficient permissions` 가 나왔다면 현재 로그인 사용자의
`admins/{uid}` 문서가 비어있거나, `BizAccountsPage` 를 **업체 계정으로
열어버린 경우**(admin 권한 없음) 발생.

판정:
- **이미지 업로드 alert 와 인과 관계 없음**
- **사용자가 admin 권한 없이 BizAccountsPage 에 접근한 흔적**으로 추정
  (또는 admins/{uid} 문서 누락)
- 별도 PR 에서 처리 필요. 본 이미지 버그 수정 시 함께 다루지 않을 것
