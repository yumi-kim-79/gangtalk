## 0. TL;DR

- **배너 슬라이드 = PR #127 회귀 (확정)**: `.gt-slider-track { position: absolute; inset: 0 }` 이 flex slider 의 **자식 가로 나열 패턴**을 깨뜨림
  - 이전 (`width:100%; height:100%`) → flex nowrap + 자식 `flex:0 0 100%` × 3 → 자식 총 300% 로 옆으로 나열 → translateX 로 이동
  - 이후 (`position:absolute; inset:0`) → track width 를 부모 폭 100% 로 **강제 확정** → 브라우저가 자식 3개를 부모 안에 배치하려다 배치 실패 (min-content 100% × 3 이 컨테이너 폭 초과) → **자식이 겹치거나 이동 무효**
- **해결**: `.gt-slider-track` 을 원상 복구 (`width:100%; height:100%`). `.gt-slider-bar` 의 `min-height: 140px` (PR #127) 은 **유지** — 이것만으로 부모 명시적 height 확보 → 자식 percentage 상속 정상. `inset:0` 은 애초에 불필요했음
- **Top5 "2개만 보임" 원인은 PR #127 이 아닐 가능성 큼**:
  - `.top-row / .rs-scroller` CSS 조건 정상 (`display:flex; overflow:auto`)
  - PR #127 이 추가한 `.m-thumb / .rs-thumb min-height: 100px` 는 폭 계산에 무관 (aspect-ratio 로 역계산해도 min-width 178 < mini min-width 180 이라 무영향)
  - **더 유력한 원인**: `.mini` 마크업의 `@touchmove.passive` 핸들러가 iOS 에서 가로 스크롤 우선권 못 잡음 (진단 §4-3 후보 D)
- **PR #127 부분 롤백 + Top5 는 별개 fix 필요**:
  - 배너: `.gt-slider-track` 만 원상 복구 (min-height 는 유지)
  - Top5: 별도 조사 (touch-action / 상위 컨테이너 max-width 등)

## 1. 배너 슬라이드 가로 이동 메커니즘

### 1-1. 마크업 (`GangTalkPage.vue:7-22`)
```html
<section class="gt-slider-bar">
  <div class="gt-slider-track"
       :style="{ transform: `translateX(-${sliderIdx * 100}%)` }">
    <div v-for="slide in sliderItems" class="gt-slide">
      <img class="gt-slide-img" ... />
    </div>
  </div>
</section>
```

**작동 원리 (flex slider 표준 패턴)**:
1. `.gt-slider-bar` = 뷰포트 (overflow: hidden 으로 슬라이드 밖 숨김)
2. `.gt-slider-track` = 자식(슬라이드)들을 가로로 나열하는 컨테이너
   - flex + nowrap → 자식이 밖으로 나가는 것 허용
   - 총 폭 = 자식 개수 × 100% (또는 자식마다 100% flex-basis)
3. `.gt-slide` = 개별 슬라이드
   - `flex: 0 0 100%` = "부모 폭 100% 를 요구" — shrink 없이
4. `translateX(-${idx * 100}%)` 로 track 을 왼쪽으로 이동 → 다음 슬라이드 노출

### 1-2. PR #118 이전 (정상 작동)
```css
.gt-slider-bar { height: 180px; overflow: hidden; }
.gt-slider-track { display: flex; width: 100%; height: 100%; transition: transform 0.5s ease; }
.gt-slide { flex: 0 0 100%; width: 100%; height: 100%; }
```

**동작**:
- `.gt-slider-track` width:100% = 부모(뷰포트) 폭 = 412px (모바일)
- 자식 3 개 각각 flex-basis:100% = 100% of parent = 412px 요구
- flex nowrap → 3 자식이 밖으로 나감 (총 폭 1236px)
- `.gt-slider-bar overflow:hidden` 이 넘친 부분 숨김
- translateX(-100%) = 412px 왼쪽 이동 → 2번째 슬라이드 노출
- ✅ **정상**

### 1-3. PR #118 이후 (height 이슈 발생)
```css
.gt-slider-bar { aspect-ratio: 12/5; overflow: hidden; }   /* height: auto */
.gt-slider-track { width: 100%; height: 100%; }             /* percentage 상속 시도 */
.gt-slide { flex: 0 0 100%; width: 100%; height: 100%; }
```

- 일부 브라우저에서 부모 `aspect-ratio` (auto height) → 자식 `height: 100%` 상속 실패 → 자식 height=0 → 슬라이드 안 보임
- **가로 이동 자체는 여전히 작동** (width 100% 정상)
- 진단 §4-1 옵션 A/B 필요

### 1-4. PR #127 (문제 발생)
```css
.gt-slider-bar {
  aspect-ratio: 12/5;
  min-height: 140px;                              /* + fallback (OK) */
}
.gt-slider-track {
  position: absolute;                              /* ← ★ 회귀 원인 */
  inset: 0;                                        /* ← ★ 회귀 원인 */
  display: flex;
  transition: transform 0.5s ease;
}
.gt-slide {
  flex: 0 0 100%;
  height: 100%;
}
```

**★ 회귀 메커니즘**:
- `position: absolute; inset: 0` → **track 의 width 를 부모 폭 100% 로 강제 확정** (left:0 + right:0 = width 100%)
- 이제 flex 컨테이너 (`.gt-slider-track`) 의 실제 폭 = 부모 폭 = 412px (고정)
- 자식 3 개 각각 `flex: 0 0 100%` = flex-basis 100% of 412 = 412px 요구
- flex 컨테이너 확정 폭 412 vs 자식 총 요구 폭 1236 → **flex 계산 충돌**
- 브라우저 처리 (매우 상이):
  - **크롬**: nowrap 이라 자식 밖으로 나감 → 이전과 동일 작동 (가로 이동 정상일 수도)
  - **iOS Safari / 일부 안드로이드**: absolute 컨테이너 안의 flex 자식들이 **컨테이너 폭 안으로 auto-shrink** → 자식들이 겹침 → translateX 이동해도 시각적 이동 없음
- **가로 이동 안 됨 = 이 auto-shrink 케이스**

### 1-5. 왜 이전 `width:100%; height:100%` 는 되고 `absolute; inset:0` 은 안 되나?
- `width: 100%` 는 static/relative layout → 부모의 "content-width" 를 참조. 이때 부모 `.gt-slider-bar { overflow:hidden }` 로 자식 nowrap flex 컨테이너의 확장이 허용됨
- `position: absolute; inset: 0` 은 **containing block 의 padding-box 크기** 로 확정 → containing block = `.gt-slider-bar` (position:relative). 이 크기가 aspect-ratio 로 확정된 폭×높이 (412×172)
- **absolute 는 특히 flex 컨테이너로 사용할 때 자식이 컨테이너 안에서 shrink 되도록 브라우저가 계산할 가능성이 있음** (spec 자체는 flex 자식 밖으로 나감을 허용하지만 브라우저마다 다름)

### 1-6. 정답 (배너)
- **PR #127 의 `min-height: 140px` 는 유지** — 이것만으로도 aspect-ratio 미지원 브라우저에서 부모 명시적 height 확보 가능. 자식 percentage 상속 정상 작동
- **`.gt-slider-track` 의 `position: absolute; inset: 0` 되돌리기** → `width: 100%; height: 100%`

**정확한 fix 코드**:
```css
.gt-slider-bar {
  position: relative;
  overflow: hidden;
  width: 100%;
  aspect-ratio: var(--gt-slider-aspect, 12 / 5);
  min-height: 140px;         /* PR #127 유지 — 이걸로 자식 percentage 상속 OK */
  background: #f0f0f0;
}
.gt-slider-track {
  /* PR #127 롤백 — flex slider 는 자식 가로 나열 가능해야 함 */
  display: flex;
  width: 100%;
  height: 100%;
  transition: transform 0.5s ease;
}
.gt-slide {
  flex: 0 0 100%;
  height: 100%;
  position: relative;
  overflow: hidden;
}
```

## 2. Top5 "2개만 노출"

### 2-1. 마크업 (`StoreFinder.vue:198-235`)
```html
<div v-for="sec in topLists" class="top-sec sf-top-sec">

```

### 2-2. CSS 조건 (`StoreFinder.vue:2275`)
```css
.top-row { display:flex; gap:8px; overflow:auto; padding-bottom:4px }
.mini { min-width: 160px; ... }
.sf-tops :deep(.mini) { min-width: var(--card-min-width, 180px); }   /* PR #120: 200→180 */

```

**계산 (모바일 412)**:
- 카드 5 개 × 180 + gap 12 × 4 = 948
- 화면 폭 380 (콘텐츠) 초과 → **overflow:auto 가로 스크롤 조건 만족**

### 2-3. PartnersPage `.rs-scroller` (`:1800-1813`)
```css
.rs-scroller {
  display: flex; gap: 10px; overflow: auto;
  scroll-snap-type: x mandatory;
  --cards-per-view: 2.5; --gap: 10px;
}
.rs-card {
  flex: 0 0 auto;
  width: calc((100% - (var(--gap) * (var(--cards-per-view) - 1))) / var(--cards-per-view));
  min-width: 220px;
}
.pp-top-sec .rs-card { min-width: var(--card-min-width, 180px); }
```

- `--cards-per-view: 2.5` 는 **의도된 값** — "한 화면에 2.5개 보이게" 디자인 원본
- min-width 180 이 우세 → 카드 폭 180px
- 5 카드 × 180 = 900 + gap = 940 → 초과 → 스크롤 필요

### 2-4. "2개만 보임" 은 정상 (스크롤 못 함이 진짜 문제)
- 화면에 첫 2 개 (또는 2.5 개) 표시되고 나머지는 가로 스크롤 뒤에 숨음 — 이건 **의도된 디자인**
- 사용자 인식 "2개만 노출" = 실제는 나머지도 오른쪽에 있음, **가로 스크롤/스와이프가 안 됨** 이 진짜 이슈

### 2-5. PR #127 의 `.m-thumb / .rs-thumb min-height: 100px !important` 가 Top5 를 깼는지?
- `.m-thumb`: `aspect-ratio: 16/9; width: 100%; min-height: 100px`
- aspect-ratio 로 min-height 100 → min-width 역계산 = 100 × 16/9 = **~178px**
- `.mini min-width: 180` 이 이미 더 크므로 **폭 영향 0**
- **PR #127 이 Top5 가로 이동을 깬 원인은 아님** (CSS 조건만 볼 때)

### 2-6. Top5 스크롤 안 되는 진짜 원인 후보
| 후보 | 검증 |
|---|---|
| (A) `overflow: auto` 미적용 | ❌ `.top-row / .rs-scroller` 모두 정상 |
| (B) 부모 `overflow-x: hidden` 상위 차단 | 확인 필요 (`.sf-tops / .page / body`) |
| (C) 카드 총 폭이 컨테이너 폭 이하 → 스크롤 불필요 | 5×180=900 > 380 초과 확실 → 배제 |
| (D) `@touchmove.passive` 로 인한 iOS Safari 가로 스크롤 인터셉트 | **매우 유력** — `StoreFinder.vue:229` 참조 |
| (E) `touch-action` CSS 로 가로 팬 금지 | 확인 필요 |
| (F) `.mini` 자체 `overflow: hidden` | 자식만 잘림, 부모 스크롤 무관 → 배제 |

**가장 유력 = 후보 D** — 실제 브라우저 렌더는 정상 (카드 5개가 오른쪽으로 나가 있음). 사용자가 스와이프하면 `@touchstart / @touchmove.passive` 가 tap 판별 로직 실행 → **`.passive` 라 브라우저 스크롤 최적화 유지되지만 tap 로직 자체가 이벤트를 소비**하지 않음. 그러나 iOS Safari 에서 `touchstart` 리스너 존재 자체만으로 스크롤 지연 발생 가능

**정확한 검증 방법**:
1. DevTools → 가게찾기 진입 → `.top-row` 우클릭 → Computed → `overflow-x` 값 확인 (auto 여야 함)
2. JS 콘솔: `document.querySelector('.sf-tops .top-row').scrollWidth` → `clientWidth` 보다 커야 함
3. `touch-action` 값 확인 (모든 부모 컨테이너 체크)
4. `.mini` 의 `@touchmove` 리스너 제거해서 스크롤 되는지 테스트
