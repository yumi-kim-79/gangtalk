# 배너/Top5 렌더링 개수 부족 — 정밀 진단 (DOM 확인 후)

날짜: 2026-07-02
증상 (DevTools DOM 확인):
- 배너: 데이터 3장 넣었는데 DOM 에 `<article class="banner">` **1개만** 렌더링
- 가게찾기 Top5: 하퍼에 5개+ 있는데 `.top-row` 안에 `button.mini` **2개만** 렌더링
- 제휴관 Top5: 여러 개 렌더 + 스크롤 정상 (비교 대상)
범위: 진단 전용. 코드 / CSS / PR / 배포 변경 0건.

## 0. TL;DR

- **[배너 1개만 렌더]** = 코드가 **원래 `slice(-1)` / `slice(0, 1)` 로 명시 제한** — "최신 1장만" 표시하는 원래 설계
  - **자동 넘김 로직 자체 존재 안 함** (setInterval/transform 없음, 인디케이터 3점은 정적 장식)
  - 사용자 인식 "자동 넘김 안 됨" = 원래부터 없음 (오해)
  - **여러 장 슬라이드 원하면**: 코드를 슬라이더로 재작성 필요 (강톡 `sliderItems` + `setInterval` 패턴 이식)
- **[가게찾기 Top5 2개만 렌더]** = **`topFromRanks` + `topLists` 폴백 로직**의 조건 부족
  - `topRanks['hopper']` 배열에 관리자가 지정한 id 중 **필터 (`isApproved` / `exposedHere` 등) 통과되는 유효 store 가 2개**
  - `list = ranked.length ? ranked : topByCat(c.key)` — **`ranked.length` 가 0 이 아니면 자동 폴백 안 함**
  - `ranked` 가 2개이면 그대로 2개 반환 → DOM 에 2개 렌더
- **[제휴관 Top5 여러 개 렌더]** = `partnerTopRanks[k]` 지정에 유효 partner 가 여러 개 (5개 채워짐 or 폴백 발동)
- **핵심 차이**:
  - **가게찾기**: `ranked.length ? ranked : fallback` — 있으면 그대로 (부족해도 채움 안 함)
  - **제휴관**: 동일 폴백 조건이지만 지정 항목이 모두 유효 → 5개 채워짐
- **[강톡 슬라이더]** = 마크업 `v-for="sliderItems"` 3장 모두 DOM 에 렌더. sliderIdx transform 로 이동. DOM 개수 문제 아님 (별개 이슈)

### 2-2. "2개만 렌더" 의 정확한 원인

**폴백 조건**: `list = ranked.length ? ranked : topByCat(c.key)`
- `ranked.length` 가 **0 이 아니면** ranked 그대로 사용
- **부족해도 자동 보충 안 함** — 2개면 2개 반환

**시나리오**:
1. **`topRanks['hopper']`** 배열에 관리자가 5개 id 지정
2. `topFromRanks` 가 그 5개 id 를 storeIndex 조회
3. 필터 (`!!s`, `isApproved`, `exposedHere` 등) 로 걸러냄
4. **통과되는 유효 store 가 2개** → `ranked` = 2개 배열
5. `ranked.length === 2 !== 0` → 자동 폴백 (topByCat) 안 함
6. `list = ranked` (2개) → 마크업 `v-for="sec.list"` → **DOM 2개**

**필터 통과 못한 3개 후보**:
- (a) `!!s === false`: storeIndex 조회 실패 (**topRanks id 가 삭제된 가게 or 존재 안 함**)
- (b) `isApproved` 실패: 승인 취소된 가게
- (c) `exposedHere` 실패: `exposure.gangtalk` false 로 지정된 가게 (관리자가 노출 OFF 함)
- (d) region 필터 실패: 지역 필터 활성인 경우

**가장 유력**: (a) 또는 (c) — 관리자가 예전에 topRanks 지정했는데 그 가게가 삭제됐거나 노출 OFF 됨. topRanks 배열 자체는 갱신 안 됨

### 2-3. 제휴관 Top5 정상 동작 코드 비교

**PartnersPage `topByCat(k)`** (`PartnersPage.vue:1256-1281`):
```js
const topByCat = (k) => {
  const ids = Array.isArray(partnerTopRanks.value?.[k]) ? partnerTopRanks.value[k] : []

  // 1) 관리자 지정 순서 우선
  if (ids.length) {
    const idToPartner = new Map(partners.value.map(p => [String(p.id), p]))
    const ordered = []
    for (const id of ids) {
      const p = idToPartner.get(String(id))
      if (!p) continue
      if (p.category !== k) continue
      if (region.value !== 'all' && normRegion(p.region) !== region.value) continue
      ordered.push(p)
      if (ordered.length >= 5) break
    }
    if (ordered.length) return ordered      // ★ 통과 항목 있으면 그대로 (부족해도 폴백 안 함)
  }

  // 2) 폴백 — 자동 score 정렬 (기존 동작 보존)
  return partners.value
    .filter(p => p.category === k)
    .filter(p => (region.value === 'all') || (normRegion(p.region) === region.value))
    .slice()
    .sort((a, b) => score(b) - score(a))
    .slice(0, 5)
}
```

**분석**:
- **가게찾기와 폴백 조건 완전 동일** (`ordered.length` 0 일 때만 폴백)
- 제휴관 이 잘 되는 이유:
  - **`partnerTopRanks['ps']` 등에 지정된 partner 가 모두 유효 (필터 통과 5개)** — 관리자가 최신 상태로 유지
  - 또는 지정 안 된 카테고리라 폴백 발동 (자동 score 정렬 5개)

**즉 코드 로직은 두 페이지 동일**. **데이터 상태 차이**로 인해 렌더 개수 다름.

## 5. 결론

- **배너 "1개만 렌더" = 원래 설계** (`slice(1)` 로 명시 제한). StoreFinder/PartnersPage 는 원래 슬라이더 아님. 여러 장 원하면 별도 PR 필요 (강톡 패턴 이식)

  - **fix 옵션 A**: 폴백 로직에 `< 5` 조건 추가로 나머지 자동 채움
