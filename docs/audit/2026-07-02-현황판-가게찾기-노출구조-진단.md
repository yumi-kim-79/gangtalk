# 현황판 / 가게찾기 노출 구조 재설계 — 진단

날짜: 2026-07-02
목표 구조:
1. 업체 자가가입 → 관리자 승인 → **가게찾기 노출** (현재는 현황판까지 자동)
2. 현황판 = 가게찾기 노출된 업체 중 관리자가 별도 지정한 가게만
3. 현황판 ⊂ 가게찾기 (현황판 지정 = 가게찾기에도 있음)
4. 관리자 페이지에서 현황판 노출 ON/OFF 토글

범위: 진단 전용. 코드 / 룰 / PR / 배포 변경 0건.

## 0. TL;DR

- **현재 문제**: `exposure.gangtalk` 필드 **1개가 가게찾기 + 현황판 양쪽 노출을 동시 결정**. 승인 시 자동 `true` set → 승인=현황판 자동 노출 = 사용자 목표와 다름
- **동일 필드 사용 검증**: MainPage `EXPOSURE_KEY='gangtalk'` (line 638) + StoreFinder `EXPOSURE_KEY='gangtalk'` (line 1239) → 100% 동일
- **권장 구조 (옵션 A)**: 필드 분리
  - `exposure.gangtalk` (기존, 유지) = **가게찾기 노출** (rename 없이 의미만 재정의)
  - `exposure.dashboard` (신규) = **현황판 노출** (별도 관리자 지정)
- **주의점 (마이그레이션)**: 현재 현황판에 떠 있는 가게들 (레이블/달토/유앤미 등) 은 `exposure.dashboard` 필드 미보유 (undefined). 정책 "undefined = 미노출" 으로 하면 **PR 배포 순간 현황판에서 모두 사라짐** → 배포 전 관리자가 지정 필요
- **PR 4 단계 권장**: 관리자 토글 UI + dashboard 필드 신설 (회귀 0) → 사용자가 지정 → MainPage 조건 변경 → 승인 로직 정합

## 7. 마이그레이션 필요성 (⚠️ 핵심)

### 7-1. 현재 현황판 표시 가게
- 실제 값: `approved:true, exposure.gangtalk:true`
- 새 구조 배포 시 MainPage 가 `exposure.dashboard` 를 봄 → **필드 없음 (undefined)**
- 정책 `exposure.dashboard === undefined ? false : val` 이면 → **전원 사라짐**
- 정책 `exposure.dashboard === undefined ? true : val` 이면 → 기존 노출 유지 (사용자 요구 위반 — 자동 노출)

### 7-2. 두 정책의 트레이드오프
| 정책 | 배포 직후 | 지속 사용 | 결론 |
|---|---|---|---|
| undefined = false (미노출) | **현황판 텅 빔** | 관리자가 지정한 것만 노출 (정확) | 지정 후 배포 필요 |
| undefined = true (노출 유지) | 기존 유지 | 자가가입 신규도 자동 노출 (문제) | ❌ |

→ **정책은 undefined = false (미노출)** 로 가야 사용자 목표 부합.
→ 배포 전 관리자가 기존 노출 가게들에 `exposure.dashboard:true` 지정 필요.

### 7-3. 마이그레이션 3 옵션
**옵션 M1 — 관리자가 UI 로 수동 지정** (권장)
- PR 1 (토글 UI) 배포 → 관리자가 Tab 1 에서 원하는 가게 지정 → PR 2 (MainPage 조건 변경) 배포
- 장점: 관리자 결정권. 실수 없음
- 단점: 관리자 수작업 (~ 20 개 가게 × 클릭)

**옵션 M2 — 스크립트 배치 마이그레이션**
```js
// Firebase Console 또는 admin CLI
const q = query(
  collection(db, 'stores'),
  where('approved', '==', true),
  where('exposure.gangtalk', '==', true),
)
const snap = await getDocs(q)
const batch = writeBatch(db)
for (const doc of snap.docs) {
  batch.update(doc.ref, { 'exposure.dashboard': true })
}
await batch.commit()
```
- 장점: 자동, 즉시
- 단점: **현재 표시 중인 가게 = 자동 현황판 노출** — 사용자 목표 (관리자가 지정) 위반. 관리자가 다시 대량 OFF 해야 함
- **권장 안 함** (배포 목표와 어긋남)

**옵션 M3 — 이중 필드 체크 (임시)**
```js
// MainPage exposedHere 수정
const exposedHere = (s) => {
  const exp = s?.exposure || {}
  if (exp.dashboard !== undefined) return !!exp.dashboard   // 신규 우선
  return !!exp.gangtalk                                       // 폴백
}
```
- 장점: 배포 직후 회귀 0
- 단점: 자가가입 신규도 자동 노출 (승인 시 `exposure.gangtalk:true` 만 set 이라면 자동 통과)
- **자가가입 승인 시 자동으로 `exposure.gangtalk:true` 만 set → 신규 승인 가게도 현황판 노출 됨** ← 목표 위반
- 해결: 승인 로직에서 `exposure.gangtalk:true, exposure.dashboard:false` 명시 set
- 옵션 M1 대비 안전 마진 크지만 관리자 UI 지정 UX 는 여전히 필요

**최종 권장**: **M1 (관리자 UI 지정)** — 배포 순서만 정확히
