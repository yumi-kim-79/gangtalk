## A. firestore.rules 의 read 규칙 (직접 확인)

| 경로 | 룰 위치 | read | 비고 |
|------|--------|------|------|
| `vendors/{vendorId}` | ❌ **없음** | (default deny) | 1차 원인 |
| `vendors/{vendorId}/status/{statusId}` | ❌ **없음** | (default deny) | 부가 |
| `news/{docId}` (탑레벨 collection) | ✅ `firestore.rules:179` | `if true` | OK |
| `admin/{docId}` | ❌ **없음** | (default deny) | 1차 원인 — `admins` (복수형, 운영자 권한) 와 **다름** |
| `dashboard/{docId}` | ❌ **없음** | (default deny) | 1차 원인 |
| `config/marketing` (doc) | ✅ `firestore.rules:33-36` `/config/{docId}` | `if true` | **공개 read** — 순서 데이터의 실제 경로 |
| `config/marketing/{sub}/{doc}` | ✅ `firestore.rules:39-42` `/config/{docId}/{document=**}` | `if true` | **공개 read** — `adBannersFinder/prod` 등 |
| `config/marketing` (line 45-47 중복) | ⚠️ `firestore.rules:45-47` | `if isAdmin()` | **두 룰이 같은 doc 매칭 → Firestore OR 로직**: `true OR isAdmin() = true` → 결국 공개 read |
| `stores/{id}` | ✅ `firestore.rules:73-86` | `if true` | OK |
| `rooms_biz/{id}` | ✅ `firestore.rules:93-100` | `if true` | OK |

**중요한 발견 — `config/marketing` 의 룰 중복**:
- `/config/{docId}` (line 33-36): `allow read: if true`
- `/config/marketing` (line 45-47): `allow read, write: if isAdmin()`
- 두 룰이 모두 `/config/marketing` 도큐먼트에 매칭됨
- Firestore Security Rules 는 **여러 매칭 룰 중 하나라도 통과하면 허용** (OR-logic)
- 결과: `config/marketing` 은 **공개 read 됨** (=`true || isAdmin()` = `true`)
- 의도와 다르게 동작하는 룰이지만 사용자 페이지의 읽기는 정상 작동 (다행)

## D. VITE_FCM_VAPID_KEY 미주입 원인 (별도)

### 사실
- 사용 위치: `src/lib/messaging.js:66, 128` 의 `import.meta.env.VITE_FCM_VAPID_KEY`
- 선언 위치: 루트 `.env` (`VITE_FCM_VAPID_KEY=…`)
- **현재 로컬 `.env` 파일 존재하지 않음** (`test -f .env` → 부재 확인)

### 원인 추정
- Sprint 0 PR 에서 `git rm --cached .env functions/.env` 실행
- `--cached` 는 **추적만 끊고 워킹 디렉토리 파일은 유지** 하는 게 정상
- 그런데 현재 로컬에 `.env` 파일 자체가 없음 → **사용자 또는 별도 작업이 실제 파일도 삭제**한 것으로 추정
- Vite 는 빌드 시점에 루트 `.env` 를 읽어 `VITE_*` 를 `import.meta.env` 에 주입. 파일 없으면 전부 undefined

### 영향 범위 (.env 부재 시)
| 변수 | 영향 |
|------|------|
| `VITE_FCM_VAPID_KEY` | FCM 토큰 발급 실패 → 푸시 알림 동작 안 함 (콘솔 경고만) |
| `VITE_GMAPS_API_KEY` | 가게 지도 (`MapView.vue`) 로드 실패 |
| `VITE_RECAPTCHA_ENTERPRISE_KEY` | AppCheck 초기화 시 `firebase.js:90` 하드코딩 폴백 키 (`6LcrdwgsAA...Qsoz`) 사용 → 운영 폴백 동작 |
| `VITE_API_PROXY_TARGET` | dev 서버 `/api` 프록시 기본값 `http://localhost:3000` 사용 |

### 수정 방향 (사용자 수동 액션)
1. 백업해 둔 `.env` 복원 또는 새로 작성 (시크릿은 코드에 넣지 말 것)
2. `VITE_FCM_VAPID_KEY` 만 필요하면 한 줄만이라도 추가:
   ```
   VITE_FCM_VAPID_KEY=<FCM 콘솔의 웹 푸시 인증서 공개 키>
   ```
3. (선택) `.env.example` 을 새로 만들어 필요한 변수 키 이름만 기재 → 다음 클론에서 참고 가능

## E. 권한 에러 — 안전한 수정 방향

### E-1. `vendors` 컬렉션

**현재 데이터 성격**: 가게 운영 시트(`/sheets/vendors/update`, `/sheets/vendors/bootstrap` Cloud Function 으로 동기화) 의 미러. `name`, `totalRooms`, `totalNeeded`, `totalCurrent`, `congestion`, `updatedAt` 등 가게별 집계 정보.

**민감도 평가**: ⚠️ **공개 권장**. 이미 `stores` 컬렉션이 공개 read 이고, vendors 의 정보는 stores 정보의 집계 미러일 뿐 새로 민감한 필드 없음. 가게의 totalRooms/totalNeeded 같은 운영 통계는 사용자 페이지 (현황판) 가 노출하려고 만든 데이터.

**룰 제안 (수정은 다음 턴에)**:
```
match /vendors/{vendorId} {
  allow read: if true;
  allow write: if isAdmin();    // 시트 동기화는 Admin SDK 우회
}
match /vendors/{vendorId}/status/{statusId} {
  allow read: if true;
  allow write: if isAdmin();
}
```

### E-2. `admin/news`, `dashboard/news` (단일 doc)

**현재 데이터 성격**: 뉴스 표시를 위한 **폴백 소스**. 코드 (`MainPage.vue:721-748` `subNewsDoc`) 는 데이터 형태를 추정만 함 (`data.items`, `data.newsItems`, `data.list`, 또는 단일 `data.title/text`). **실제로 이 경로에 데이터가 쓰여 들어가는 코드는 없음** — 즉 사용 안 되는 레거시 폴백.

**민감도 평가**: 🟢 **공개해도 무방** (어차피 빈 doc) **OR 권장: 구독 자체 제거**.

**옵션 A — 룰 추가 (변화 최소)**:
```
match /admin/{docId} {
  allow read: if true;
  allow write: if isAdmin();
}
match /dashboard/{docId} {
  allow read: if true;
  allow write: if isAdmin();
}
```
효과: 에러 사라짐, 데이터 없으므로 `snap.exists() === false` 분기 정상 동작 (`MainPage.vue:725-728`).

**옵션 B — 코드에서 폴백 구독 제거 (더 깔끔)**:
`MainPage.vue:763-769` 의 `subNewsDoc('admin', 'admin', 'news')` 와 `subNewsDoc('dashboard', 'dashboard', 'news')` 호출 제거. 실제 뉴스는 `config/marketing.newsline` (이미 정상) 과 `news` collection (이미 정상) 에서 충분.

권장: **B (제거)** — 실제 사용 안 하는 룰을 추가하는 것보다 데드 코드 정리가 안전.

### E-3. `config/marketing` 룰 중복 정리 (선택)

`firestore.rules:33-36` 의 `/config/{docId}` 와 `:45-47` 의 `/config/marketing` 이 충돌. OR 로직으로 공개 read 가 이김. 의도가 admin only 였다면 line 33-36 을 `signedIn()` 또는 `isAdmin()` 으로 조정해야 함. 단 현재 공개 read 가 **순서 데이터의 사용자 페이지 노출에 필요** 하므로 변경 시 신중 (homeOrder/topRanks 가 사용자에게 안 보이게 될 수 있음).

권장: **현 상태 유지**. 단 룰 주석을 명확히 (line 45-47 이 dead/conflicting 임을 표시) 정리.
