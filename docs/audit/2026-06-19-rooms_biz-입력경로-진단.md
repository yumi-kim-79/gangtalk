## 5. legacy stores 폴백과의 관계

### 5-1. stores 의 source of truth 여부

- `MainPage.applyRoomsBiz` 의 폴백 우선순위:
  - `rbActive=true` → `byRb.rooms/people` (rooms_biz 우선)
  - `rbActive=false` → `legacyMatch = s.match` (stores 폴백)
- **즉 rooms_biz 가 source, stores 는 legacy 폴백** — 진단 §1 의 분류와 일치

### 5-2. stores 본 doc 의 match/persons 가 0 인 이유

`StoresManagePage.saveAllMetrics:490-494`:
```js
batch.update(doc(fbDb, 'stores', s.id), {
  match, persons, totalRooms, maxPersons,
  ...
})
```

→ admin 일괄 저장이 stores 본 doc 의 match/persons 도 함께 0 으로 갱신
→ legacy 폴백도 0 → "잠깐 진짜 값" 이 보이지 않는 상태

### 5-3. 다른 시드/더미 데이터 가능성
- `seed_*.json` 같은 시드 스크립트 grep — 없음 (확인 필요)
- 13개 store 가 실서비스 가입 업체인지, 테스트 데이터인지 사용자만 확정 가능
- 출시 전 점검 보고서 H-5 ("더미 데이터 정리") 항목과 연동
