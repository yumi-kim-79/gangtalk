# 업체 자가입력 → 승인 → 노출 흐름 진단

**날짜**: 2026-06-18
**범위**: 관리자가 업체계정만 생성(가게연결 없이) → 업체 본인이 업소정보 입력/저장 → 관리자 승인 → 사용자 화면(현황판) 노출 파이프라인
**전제**: 진단 전용. 코드/룰 수정·PR·배포 없음.
**핵심 결론**:
1. **승인→노출 파이프라인은 이미 완벽 구현됨** — 룰 / 사용자 필터 / 관리자 승인 액션 모두 정상
2. **빠진 한 가지** = **업체가 본인 출근업소를 신규 생성하는 UI/로직**. `BizMyStorePage` 가 update only, "연결된 가게 없음" 안내만
3. **`createBizAccount` 의 storeId 매개변수 제거 가능** — 코드 사실 검증 결과 `storeId` 없어도 정상 동작 (계정만 생성)
4. firestore.rules `stores create` 룰이 이미 본인 uid 로 자가등록 허용 — **변경 0건**
5. 신규 생성 시 `applyStatus: 'pending', approved: false` 박으면 사용자 화면 자동 미노출 → 관리자 승인 후 자동 노출

## 1. 현재 흐름 정밀 분석

### 1-1. `createBizAccount` (`functions/index.js:2447-2535`) — 단계별

```js
exports.createBizAccount = onCall({ cors: ADMIN_CORS }, async (req) => {
  assertCallerIsAdmin(req)
  const { email, password, storeName, storeId } = req.data

  // 1) Auth 사용자 생성
  const userRecord = await admin.auth().createUser({ email, password, displayName: storeName })
  const uid = userRecord.uid

  // 2) users/{uid} 문서 생성 (storeId 무관)
  await db.collection('users').doc(uid).set({
    type: 'company', accountKind: 'storeOwner',
    profile: { email, nickname: storeName, ... },
    company: { name: storeName },
    createdBy: 'admin', ...
  }, { merge: true })

  // 3) storeId 가 주어지면 stores 매핑 (선택)
  if (storeId) {
    await db.collection('stores').doc(storeId).set(
      { ownerId: uid, ownerEmail: email, updatedAt: ... },
      { merge: true },
    )
  }
  return { ok: true, uid, email }
})
```

→ **`storeId` 는 이미 선택적**. 안 주면 stores 매핑 단계 건너뛰고 users + Auth 만 생성. `users` 문서에 storeId 필드 없음 (사용 안 함).

### 1-2. `BizAccountsPage.vue` (관리자 UI) — 가게 연결 드롭다운

`:88,141` 모달의 `<select v-model="form.storeId">` 가 stores 컬렉션 전체를 옵션으로. **선택 강제 아님** — 비워두면 createBizAccount 가 storeId 없이 호출됨.

→ **현재도 "가게연결 없이" 계정만 생성 가능**. UI 만 정리하면 됨

## 2. firestore.rules `stores` create 룰 — 변경 0건

`firestore.rules:108-118`:
```
match /stores/{id} {
  allow read: if true;
  allow create: if signedIn() && request.resource.data.ownerId == request.auth.uid;
  allow delete: if signedIn() && (resource.data.ownerId == request.auth.uid || isAdmin());
  allow update: if signedIn() && (isAdmin() || (resource.data.ownerId == request.auth.uid && ...));
}
```

- **create**: `signedIn` + `ownerId == auth.uid` → **업체(type='company')가 본인 uid 로 자가등록 가능**. `type` 검사 별도 안 함 (signedIn 만 충분)
- 본인 update 시 ownerId 변경 금지 가드 → 새로 생성 시도 시 OK, 이후 수정 시 양도 차단

→ **룰 변경 0건**. 업체가 본인 uid 로 stores 신규 doc 만들 권한 이미 있음

## 3. 승인 → 노출 파이프라인 — 이미 완전 구현

### 3-1. 관리자 승인 액션 (`StoresManagePage.vue:531-543 approveStore`)

```js
async function approveStore(s){
  if (!confirm(...)) return
  await updateDoc(doc(fbDb, 'stores', s.id), {
    approved: true,
    applyStatus: 'approved',
    'exposure.gangtalk': true,         // ← 노출 토글도 자동 ON
    approvedAt: serverTimestamp(),
    updatedAt: serverTimestamp(),
  })
}
```

→ 승인 시 **3개 필드 동시 set**: `approved=true`, `applyStatus='approved'`, `exposure.gangtalk=true`

### 3-2. 관리자 거절 (`:545-557 rejectStore`)
```js
await updateDoc(..., {
  approved: false,
  applyStatus: 'rejected',
  rejectedAt: ...,
})
```

### 3-3. 관리자 페이지 분류 (`:232-248`)

| 분류 | 조건 |
|---|---|
| `isApproved` | `approved===true` OR `applyStatus in [approved/승인/완료]` OR (둘 다 undefined) |
| `isPending` | `applyStatus in [pending/대기/waiting/신청/검토중]` |
| `isExposed` | `exposure.gangtalk===undefined ? true : !!exposure.gangtalk` |

→ Tab 1 (노출관리) = `isApproved`. Tab 3 (승인대기) = `isPending`

### 3-4. 사용자 화면 노출 필터 (`MainPage.vue:1812-1846 isApproved`)

```js
if (s?.hidden === true) return false
if (!hasApply && !hasApprovedFlag) return true                          // 옛 데이터 호환
if (approved===true || apply in [approved/승인/완료]) return true
if (approved===false || apply in [pending/대기/waiting/신청/검토중/rejected/거절/반려]) return false
return false                                                            // 알 수 없는 값은 미노출
```

→ **`applyStatus='pending'` 박은 신규 store 는 사용자 화면 자동 미노출**. 관리자 승인 후 자동 노출

### 3-5. 추가 노출 조건
- `exposedHere(s)`: `exposure.gangtalk === false` 면 미노출. `undefined` 면 노출 (관리자 승인 액션이 자동 set)
- `isActiveAd(s)`: `adStart/adEnd` 기간 검증 — 둘 다 비면 무기한 통과

```js
async function createNewStore() {
  const uid = currentUid.value
  const email = currentEmail.value
  if (!uid) { alert('로그인이 필요합니다.'); return }

  const newId = doc(collection(fbDb, 'stores')).id        // Firestore auto-id
  await setDoc(doc(fbDb, 'stores', newId), {
    name:         form.value.name,
    phone:        form.value.phone,
    desc:         form.value.desc,
    detailDesc:   form.value.detailDesc,
    address:      form.value.address,
    hours:        form.value.hours,
    closed:       form.value.closed,
    thumb:        form.value.thumb,
    category:     form.value.category,
    region:       form.value.region,
    wage:         Number(form.value.wage || 0),
    wageType:     form.value.wageType,

    // 핵심 — 소유자 + 승인 대기 상태
    ownerId:      uid,
    ownerEmail:   email,
    applyStatus:  'pending',
    approved:     false,
    'exposure.gangtalk': false,        // 명시적 숨김 (승인 전)

    createdAt:    serverTimestamp(),
    updatedAt:    serverTimestamp(),
  })
}
```
