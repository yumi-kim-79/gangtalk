# 닉네임이 '게스트' 로 되돌아가는 회귀 진단

**날짜**: 2026-06-18
**범위**: gangtox.com 회원 프로필 — 닉네임을 수정/저장하면 즉시 표시는 바뀌지만, 새로고침/재방문 시 '게스트' 로 회귀
**전제**: 진단 전용. 코드/룰 수정·PR·배포 없음.
**결론**: **회귀 메커니즘은 (b) + (c) 결합**.
- (b) **`me.init` 의 `_listenUserDoc` onSnapshot 이 `points` 만 me.auth 에 반영, `profile.nickname` 변화는 무시** → ProfileEditSheet 저장 후 me.auth.profile.nickname 은 변경 안 됨
- (c) **새로고침 시 me.init 가 users 를 다시 읽어 me.auth 갱신**. **Firestore 의 users.profile.nickname 이 실제로 변경됐는지가 결정적**
- 저장 코드는 표면적으로 `updateDoc(users, { profile: {...} })` 호출 — 권한도 정상 (자기 자신 doc). 그런데 사용자 보고 ("게스트로 회귀") + useMyPageCore 폴백 8순위가 '게스트' 인 점으로 미루어, **users.profile.nickname 이 실제로 빈 값 또는 옛 값으로 저장됐을 가능성** 또는 **me.init 가 users doc 을 읽지 못해 빈 me.auth 상태로 폴백**

### 1-1. 동작 분석
- **Firestore users 문서 update 호출** — `:620`
- `profile` 필드 전체 객체 덮어쓰기 (spread + override)
- spread 했으니 기존 필드 보존 (단 `nicknameLower` 는 명시 안 함 → 사라짐)
- 본인 doc 이라 firestore.rules 정상 (`isOwner(uid)`)

### 1-2. nickname 값이 들어가는 경로
- `props.edit.nickname ?? props.state.profile?.nickname ?? ''`
- `??` 는 `null`/`undefined` 만 폴백 — 빈 문자열 `''` 은 그대로 통과
- → `props.edit.nickname === ''` 인 상태에서 저장 시 **users 에 nickname='' 저장됨**
- ProfileEditSheet 의 `edit` 객체 초기화 — 부모 (`MyPage.vue`) 가 `state.profile.nickname` 으로 초기 set 했다면 정상. 미초기화 시 undefined → 폴백 `state.profile?.nickname` 사용

### 1-3. catch (`:624-626`)
```js
} catch (err) {
  console.error(err)
  alert('프로필 저장 중 오류가 발생했어요.')
}
```
- 실패 시 alert. 사용자가 alert 봤다면 실패 인지 가능. 보고는 "저장 직후 표시됨" 이므로 **updateDoc 자체는 성공으로 추정** (alert 없었음)

## 2. 저장 직후 즉시 표시 (`MyPage.vue:465-501` `handleProfileSave`)

```js
const handleProfileSave = () => {
  const store = state?.value ?? state
  if (store) {
    if (!store.profile) store.profile = {}
    const p = store.profile
    const nickname = getEditField('nickname')
    if (nickname !== undefined) {
      const nick = String(nickname || '').trim()
      if (nick) {                      // ← 빈 문자열이면 패치 안 함
        p.nickname = nick
        p.nick = nick
      }
    }
    ...
  }
  if (typeof saveProfile === 'function') saveProfile()
}
```

### 2-1. 동작 분석
- **`state` 는 `useMyPageCore.js:87` 의 `computed`** → 매번 새 객체 반환
- `state.value.profile = ...` 직접 mutation → reactive 효과 일시적 (다음 computed 재실행 시 사라짐)
- 그래도 immediate 표시는 작동 (computed 가 재실행되기 전까지 mutation 보임)
- **`saveProfile()` 호출** — 위 ProfileEditSheet 의 onSave 가 emit 한 후 부모가 다시 saveProfile() 호출 (별도 함수, 무엇을 하는지 확인 필요)

### 2-2. **`me.auth.value.profile.nickname` 은 변경 안 됨**
- `handleProfileSave` 는 computed `state` 의 mutation 만 함
- me.auth (실제 source of truth) 는 안 건드림
- 즉 즉시 표시 후 새로고침하면 me.auth 가 reset 되거나 users 에서 다시 읽음

- 만약 ProfileEditSheet 의 updateDoc 가 정상적으로 nickname='강톡 관리자' 로 저장됐다면 → 새로고침 시 me.auth.profile.nickname='강톡 관리자' → 정상 표시되어야 함

### 3-2. `_listenUserDoc` onSnapshot (`store/user.js:176-197`)

- ProfileEditSheet 가 users update 시 onSnapshot 콜백 발화하지만 **`points` 만 me.auth 에 반영, nickname 변화는 무시**
- → ProfileEditSheet 저장 직후 me.auth.profile.nickname 은 여전히 옛 값. 다음 새로고침 시에만 me.init 가 users 다시 읽어 갱신

## 4. 표시 폴백 (`useMyPageCore.js:1648-1656`)

```js
const nick = computed(() => {
  return (
    p.nickname ||      // 1순위
    p.nick ||          // 2순위
    p.name ||          // 3순위
    c.nickname ||      // 4순위 (company)
    c.manager ||       // 5순위 (company)
    fromLocal ||       // 6순위 (localStorage 'user:nick' / 'nickname')
    emailId ||         // 7순위 (email @ 앞부분)
    '게스트'           // 8순위 폴백
  )
})
```

### 4-1. '게스트' 표시는 어떻게 발생?
- 1-7 순위 모두 비어있을 때만 '게스트'
- **사용자 보고대로 '게스트' 가 표시되려면 `emailId` (7순위) 도 비어있어야 함** = `me.auth.email` 도 빈 상태
- 즉 me.auth 가 전체적으로 비어있거나 `{loggedIn:false}` 상태로 추정

→ **단순히 users.profile.nickname 만 빈 게 아니라, me.auth.email 마저 비어있는 상태**

## 5. 회귀 메커니즘 정리 — 3개 후보

### 후보 A: ProfileEditSheet 저장이 users 문서를 안 건드림
- **반증**: 코드는 명백히 `updateDoc(doc(db, 'users', uid), payload)` 호출 (`:620`)
- 권한 OK (자기 자신 doc, firestore.rules `isOwner(uid)` 통과)
- catch 시 alert → 실패면 사용자가 봤을 것
- **가능성 낮음**

### 후보 B: users 문서가 정상 업데이트됐는데도 me.init 가 다시 빈 값으로 덮어씀
- me.init 는 단순히 users 를 읽어 me.auth 에 set — 빈 값으로 "덮어쓰지" 않음, 그저 읽은 그대로
- 만약 users 의 profile.nickname 이 실제로 '강톡 관리자' 라면 me.auth 도 '강톡 관리자' 가 됨
- **그런데 사용자 보고는 '게스트'** → users 의 profile.nickname 이 실제로 변경 안 됐을 가능성
  - 가설 B-1: ProfileEditSheet 의 payload 가 빈 nickname 으로 저장 (`edit.nickname === ''`)
  - 가설 B-2: ProfileEditSheet 와 다른 코드가 그 후 users 를 빈 nickname 으로 덮어씀

### 후보 C: me.init 가 users 를 못 읽음 (권한/race) → me.auth 비어있는 상태로 폴백
- `getDoc(userRef)` 실패 시 예외 발생 — try/catch 없음 (`:281` `const snap = await getDoc(userRef)` 직접 await)
- 예외 시 콜백 자체가 reject → me.auth 안 변함 → LS_AUTH 초기 ref 가 그대로 표시 (게스트 폴백)
- 단 다음 새로고침 시 다시 시도 → 성공하면 정상화
- **사용자가 새로고침 여러 번 해도 게스트** 라면 후보 C 보다 후보 B-1 가능성 높음

### 후보 D: 다른 곳에서 users.profile 을 빈 nickname 으로 덮어쓰기
- `_listenUserDoc` 은 points 만 — 무관
- me.init 의 LowerCase 자동 보정 (`:298-304`): `profile.nicknameLower`, `profile.nick` 만 set, `profile.nickname` 안 건드림
- me.init 의 추천코드 정합화 (`:326-329`): `referral.*` 만, nickname 무관
- 그 외 users update 코드 grep 으로 확인 가능

## 7. 결론 + 고칠 방향 (별도 PR — 본 진단 외)

### 7-1. 가장 유력한 시나리오
1. **`ProfileEditSheet.vue:608` 의 `props.edit.nickname ?? ...`** 에서 `edit.nickname === ''` 케이스 — 빈 문자열이 통과 → users.profile.nickname = ''
2. 새로고침 → me.init 가 users 읽음 → profile.nickname='' → me.auth.profile.nickname=''
3. useMyPageCore 표시 폴백 1-7 순위 모두 빈 → 8순위 '게스트'

### 7-2. 보조 가설
- ProfileEditSheet 닫기 → MyPage 의 `handleProfileSave` (`:464-501`) 가 `state.profile` mutation
- state 는 computed → mutation 효과 일시적
- 사용자가 보는 "저장 직후 표시됨" 은 ProfileEditSheet 의 `edit.nickname` ref 가 부모로 전달돼 표시되는 것 + handleProfileSave 의 mutation 일시 효과
- 새로고침 → state computed 재실행 → me.auth 의 빈 nickname → '게스트'

### 7-3. 후속 PR 방향
1. **`ProfileEditSheet.vue:608` 의 폴백 보강**:
   ```diff
   - nickname: props.edit.nickname ?? props.state.profile?.nickname ?? '',
   + nickname: (String(props.edit.nickname || '').trim() || props.state.profile?.nickname || ''),
   ```
   - 빈 문자열은 트림 후 falsy → 기존 nickname 으로 폴백
2. **빈 nickname 저장 거부**: ProfileEditSheet 의 onSave 시작 부분에 `if (!String(props.edit.nickname || '').trim()) { alert('닉네임을 입력해 주세요'); return }`
3. **`_listenUserDoc` 가 nickname 변화도 me.auth 에 반영**:
   ```diff
   - me.auth.value = { ...(me.auth.value || {}), points: p }
   + me.auth.value = {
   +   ...(me.auth.value || {}),
   +   points: p,
   +   profile: { ...(me.auth.value?.profile || {}), ...(data.profile || {}) },
   +   company: data.company || me.auth.value?.company,
   + }
   ```
   - ProfileEditSheet 저장 직후에도 me.auth 가 실시간 갱신 → 새로고침 없이도 정상 표시
4. **me.init 의 `getDoc` 에 try/catch 추가** → 일시 실패 시 LS_AUTH 캐시 보존, 다음 새로고침 시 재시도
