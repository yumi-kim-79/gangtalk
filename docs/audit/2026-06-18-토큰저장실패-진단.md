# 토큰 저장 실패 + 게스트 표시 — PR #79 후 잔존 진단

**날짜**: 2026-06-18
**범위**: gangtox.com 회원 사이트. PR #79 (persistence 충돌 차단 + 익명 자동 호출 폐지) 배포 후에도 "잠깐 유지 후 로그아웃" + 마이페이지 "게스트" 표시 + 추천코드 y00001 폴백
**전제**: 진단 전용. 코드/룰 수정·PR·배포 없음.
**결론**: PR #79 가 잡지 못한 **3번째 `setPersistence(browserLocalPersistence)` 호출이 `GangTalkPage.vue:2423` 에 잔존**. firebase.js 의 `indexedDBLocalPersistence` 와 race → 토큰이 indexedDB 에 안 써짐. "게스트 표시" 는 같은 뿌리의 결과 (토큰 복원 실패 → me.auth reset → 닉네임 폴백 8순위 '게스트'). 추천코드 y00001 은 **별개 문제** (CLAUDE.md Sprint 1 #6 — `reserveReferralCode` Cloud Function 미배포 폴백).

## 1. 결정적 단서 — 진짜 원인 (파일:라인)

### 1-1. **PR #79 가 못 잡은 3번째 `setPersistence` 호출** (가장 유력)

$ grep -rn "setPersistence" src/

**`GangTalkPage.vue:2420-2423`**:
```js
onBeforeMount(()=>{
  const auth = getAuth()
  setPersistence(auth, browserLocalPersistence).catch(()=>{})
  ...

```

- 회원 사이트의 **강톡 탭** 컴포넌트
- `onBeforeMount` 에서 fire-and-forget 으로 `setPersistence(browserLocal)` 호출
- 사용자가 강톡 탭에 진입할 때마다 호출
- `firebase.js:155` 의 `indexedDBLocalPersistence` 와 충돌

### 1-2. race 흐름

| t | 이벤트 | active persistence |
|---|---|---|
| 0 | 새로고침 시작 | (SDK default = browserLocal) |
| 0 | `firebase.js` 모듈 로드 → `persistenceReady` IIFE 시작 (await 안 됨) | 변경 진행 중 |
| ~10ms | `me.init` / `ensureFirebase` → `await firebaseReady` | persistence 적용 대기 |
| ~30ms | `setPersistence(indexedDB)` 적용 완료 | **indexedDB** |
| ~100ms | App 마운트 → 라우터 첫 navigation | indexedDB |
| 사용자가 강톡 탭 클릭 시 | `GangTalkPage` mount → `onBeforeMount` → `setPersistence(browserLocal)` | **browserLocal 로 덮임** |
| 사용자가 로그인 (탭 진입 후) | `signInWithEmailAndPassword` → token 이 **localStorage 에 저장** | browserLocal |
| 사용자 새로고침 | `firebase.js` 가 다시 `setPersistence(indexedDB)` 적용 → SDK 가 **indexedDB 에서 token 찾으려 함** | indexedDB |
| 복원 단계 | **localStorage 에 있는 token 못 읽음** → onAuthStateChanged null | indexedDB |
| ~2.5s | grace 만료 → me.init 가 LS_AUTH reset → 마이페이지 "게스트" 표시 | indexedDB (텅 빔) |

**핵심**: 사용자가 한 번이라도 강톡 탭에 진입한 후 로그인했다면 token 이 localStorage 에 저장됨. 그 후 새로고침 시 firebase.js 가 indexedDB 를 활성 persistence 로 만들어 SDK 가 localStorage 의 token 을 못 봄.

### 1-3. 사용자 보고 검증

- "indexedDB.databases() 에 `firebase-app-check-database` 만 있고 `firebaseLocalStorageDb` 없음" → **token 이 indexedDB 에 안 써졌음 확정**
- "잠깐 유지 후 로그아웃" → 로그인 직후엔 `auth.currentUser` 메모리에 살아있어 동작, 새로고침 시 복원 실패
- "마이페이지에 게스트" → 새로고침 후 me.init grace 만료 → LS_AUTH reset → 닉네임 폴백 8순위 ('게스트')

## 2. "게스트 표시" 는 같은 뿌리의 결과

### 2-1. 닉네임 폴백 순서 (`src/composables/mypage/useMyPageCore.js:1648-1656`)

```js
const nick = computed(() => {
  return (
    p.nickname ||      // 1순위: Firestore profile.nickname
    p.nick ||          // 2순위
    p.name ||          // 3순위
    c.nickname ||      // 4순위: 기업회원
    c.manager ||       // 5순위: 회사 담당자
    fromLocal ||       // 6순위: localStorage
    emailId ||         // 7순위: 이메일 ID
    '게스트'           // 8순위 폴백
  )
})
```

- `me.auth.value` 가 reset 되면 `p`(profile) 와 `c`(company) 가 빈 객체
- `fromLocal` 도 LS_AUTH/user:nick localStorage 가 reset 되면 빈
- `emailId` 도 a.email 이 없으면 빈
- → **'게스트' 폴백** 출력

### 2-2. 토큰 저장 실패 → 같은 시점에 발생

- 사용자가 본 '게스트' 는 **새로고침 후의 상태**
- 토큰 복원 실패 → me.init grace 만료 → LS_AUTH 빈 → 게스트

**즉 게스트 표시는 토큰 저장 실패의 *결과* 이지 별개 원인이 아님**. 토큰 저장이 정상화되면 자동 해결.

## 4. PR #79 가 이 케이스를 못 잡은 이유

PR #79 의 변경:
1. AuthPage 의 `setPersistence(browserLocal)` 제거
2. firebase.js 의 익명 자동 호출 폐지
3. ensureFirebase 가 `await firebaseReady`

PR #79 의 가정: "회원 빌드에서 setPersistence 호출은 AuthPage 만". `grep` 으로 모든 호출처를 봤어야 했지만 admin 빌드와 회원 빌드 구분 안 하고 admin 의 호출은 그대로 둠 (`BizLoginPage`, `AdminLoginPage`). **단 GangTalkPage 의 잔존 호출은 회원 빌드인데 놓침**.

`GangTalkPage` 는 `onBeforeMount` 라 mount 직전 1회만 호출. 사용자가 강톡 탭에 진입하지 않으면 영향 없음. 따라서:
- 사용자가 강톡 탭에 한 번도 안 들어가면 → PR #79 가 동작
- 강톡 탭 한 번이라도 들어가면 → setPersistence(browserLocal) 활성화 → 모든 후속 signIn 이 localStorage 에 저장 → 다음 새로고침 시 SDK 가 indexedDB 만 보고 복원 실패

## 5. 콘솔에서 확인 — setPersistence 적용 상태 점검 스니펫

### 5-1. localStorage / indexedDB 의 firebase 키 직접 확인

```js
// (1) localStorage 의 firebase 키 (browserLocal 폴백 흔적)
const lsKeys = Object.keys(localStorage).filter(k => k.toLowerCase().includes('firebase'))
console.log('localStorage firebase keys:', lsKeys)
lsKeys.forEach(k => console.log(`  ${k}:`, localStorage.getItem(k)?.slice(0, 200)))

// (2) indexedDB 의 모든 DB 목록
indexedDB.databases().then(dbs => {
  console.log('indexedDB databases:', dbs.map(d => d.name))
})

// (3) Firebase Auth indexedDB row 직접 조회 (있다면)
const req = indexedDB.open('firebaseLocalStorageDb')
req.onsuccess = (e) => {
  const db = e.target.result
  if (!db.objectStoreNames.contains('firebaseLocalStorage')) {
    console.log('firebaseLocalStorage object store 없음')
    return
  }
  const tx = db.transaction('firebaseLocalStorage', 'readonly')
  tx.objectStore('firebaseLocalStorage').getAll().onsuccess = (ev) => {
    console.log('indexedDB Auth rows:', ev.target.result)
  }
}
req.onerror = (e) => console.log('firebaseLocalStorageDb open error:', e.target.error)
```

### 5-2. 현재 active persistence type 추론 (간접)

// 대안: 콘솔에 다음을 출력하도록 임시 console.log 추가 후 재배포
