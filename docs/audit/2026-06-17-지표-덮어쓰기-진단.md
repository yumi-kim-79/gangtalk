## 2. `applyRoomsBiz` 의 우선순위 — 🔴 진짜 버그 위치

`MainPage.vue:1133-1195` `applyRoomsBiz` 함수의 매핑:

```js
const byRb = rbMap[id] || null
...
const legacyMatch   = Number(s?.match ?? s?.needRooms ?? 0)
const legacyPersons = Number(s?.persons ?? s?.needPeople ?? 0)

const match = Number.isFinite(byRb?.rooms)
  ? Number(byRb.rooms)        // ← 🔴 byRb.rooms === 0 도 finite!
  : (Number.isFinite(legacyMatch) ? legacyMatch : 0)

const persons = Number.isFinite(byRb?.people)
  ? Number(byRb.people)       // ← 🔴 같은 문제
  : (Number.isFinite(legacyPersons) ? legacyPersons : 0)
```

### 핵심
- `Number.isFinite(0)` 은 **true** (JavaScript 사양)
- `rooms_biz/{id}` 문서가 존재만 하고 내용이 비면 `byRb.rooms = 0`, `byRb.people = 0` 으로 set 됨 (다음 절 참조)
- 그러면 위 조건은 `byRb?.rooms === 0 → Number(0) = 0` 으로 evaluate
- legacy fallback **실행 안 됨** → 실값 10/5 가 0/0 으로 변환

### 의도된 동작 vs 실제 동작
- 주석 (`:1143-1145`): "rooms_biz 값이 있으면 그 값을 우선 사용, 없으면 legacy fallback"
- 의도: "rooms_biz 가 의미 있는 값을 들고 있으면 우선"
- 실제: "rooms_biz 가 0 이라도 그게 우선" — 0 도 의미 있는 값으로 취급

## 3. `subscribeRoomsBiz` 가 0 을 만드는 시나리오

`MainPage.vue:1320-1419` `subscribeRoomsBiz` 의 처리 (각 rooms_biz doc 마다):

```js
let pastedText = String(x.lastPastedText || x.manualText || x.bannerText || '').trim()

if (!pastedText) {
  try {
    pastedText = (await fetchLatestMessageText(bizId)).trim()   // 🐢 SEQUENTIAL await
  } catch {}
}

const inputRooms  = Number(x.needRooms  ?? 0)
const inputPeople = Number(x.needPeople ?? 0)

let rooms = 0, people = 0

if (pastedText) {
  const parsed = parseNeedFromLastPastedText(pastedText)
  rooms  = Number(parsed.rooms  ?? 0)
  people = Number(parsed.people ?? 0)
}

const isOneLine = pastedText && !/\n/.test(pastedText)
if ((rooms === 0 && people === 0) || isOneLine) {
  rooms  = Math.max(rooms,  inputRooms)
  people = Math.max(people, inputPeople)
}

rooms  = Math.max(0, Number(rooms  || 0))    // 항상 ≥ 0
people = Math.max(0, Number(people || 0))

map[id] = { rooms, people, congestion: ..., updatedAt: ... }
```

### 0 이 나오는 케이스
- `lastPastedText` / `manualText` / `bannerText` 모두 비어 있음
- 메시지도 없음 (`fetchLatestMessageText` 가 빈 문자열 반환)
- `needRooms` / `needPeople` 필드도 없거나 0

→ `map[id] = { rooms: 0, people: 0, ... }` 로 set. **byRb 가 존재함 (null 아님) + .rooms = 0**.

### 결과
applyRoomsBiz 가 `Number.isFinite(byRb?.rooms) === true` 분기를 타고 → **match = 0 으로 덮어씀**.

## 4. 왜 10초 후인가 — 타이밍 추적

### t = 0 (페이지 로드 직후)
- `firebaseReady` 완료
- `subscribe()` (stores 구독) → cache snapshot 즉시 → `baseStores.value = rows` → `applyRoomsBiz()` 호출
  - 이 시점 `roomsBiz.value = {}` 이므로 `rbMap = {}` → `byRb = null` → **legacy 사용 → 실값 표시**
- 동시에 `subscribeRoomsBiz()` 시작 → rooms_biz cache snapshot 도착 → for-loop 진입

### t = 0 ~ 10s
- **for-loop 가 sequential await** 으로 진행:
  ```js
  for (const { id, x } of entries) {
    if (!pastedText) {
      pastedText = (await fetchLatestMessageText(bizId)).trim()
    }
    ...
  }
  ```
- `fetchLatestMessageText` 한 번 호출 = 최대 **5개의 sequential Firestore getDocs**:
  1. `rooms_biz/{bizId}/messages` 쿼리
  2~5. `rooms_biz/{bizId}/rooms/{rid}/messages` 4 종 (`{bizId}_room_01`, `room_01`, `general`, `main`)
- 비어 있는 rooms_biz 문서가 10~50개면 각 ~50ms × 5 reads × N docs = **수초~십수초**
- 이 동안 사용자 화면은 t=0 의 legacy 값이 그대로 표시 ← **사용자가 본 "처음엔 정상"**

### t ≈ 10s (loop 완료)
- `roomsBiz.value = map` 일괄 set (50개 항목 모두 한꺼번에)
- `applyRoomsBiz()` 두 번째 호출
- 빈 rooms_biz doc 가 있는 stores → `byRb.rooms = 0` → **match = 0**
- 비어있지 않은 rooms_biz doc 가 있는 stores → byRb.rooms 의 실값 사용 → 정상
- rooms_biz doc 자체가 없는 stores → byRb = null → legacy 사용 → 정상
- **`stores.value` 일괄 갱신 → 모든 카드 재렌더** ← 사용자가 본 "10초 후 0으로"

### 추가 호출 가능성
- 만약 vendors 권한이 통과되면 `applyRoomsBiz` 가 또 한 번 호출되지만 (`:1461, :1549`), 권한 deny 라 무관

## 5. 권한 에러(vendors / news) 가 값 리셋의 원인인가?

### `watchWithLabel` 의 에러 처리 (`:1067-1070`)
```js
(err) => {
  console.error(`[FS][${label}] onSnapshot error:`, err)
}
```
- 에러 콜백은 console.error 만 수행
- **상태 변수 (roomsBiz.value, labelsAgg.value, newsState[...]) 를 건드리지 않음**
- → 권한 에러는 **값 리셋 원인 아님**. 콘솔 노이즈만

### vendors 권한 deny 의 실제 영향
- `subscribeVendorsSummary` 성공 콜백 (`:1432-1467`) 미실행 → `labelsAgg.value` = `{}` (기본값) 유지
- `applyRoomsBiz` 에서 `byAg = agg[String(s.name || '')] || null` → null
- `totalRooms = byAg?.totalRooms ?? s?.totalRooms ?? ...` → stores 의 legacy `s.totalRooms` 사용
- **match / persons 에는 영향 없음** (위 ① ② 분리 우선순위)

### news 권한 deny 의 영향
- `admin/news`, `dashboard/news` 두 doc 만 fail
- 다른 뉴스 소스 (`config/marketing.newsline`, `news/*`, `config/news`) 는 정상
- 화면 핫이슈 텍스트만 약간 누락 가능. **지표 숫자와 무관**

## 6. 순서(homeOrder) 도 같은 메커니즘인가?

순서 문제는 직전 진단 (`docs/audit/2026-06-17-순서-섹션매핑-진단.md`) 의 결론대로:

## 8. 수정 방향 (다음 PR 후보)

### 🔴 우선 1 — `applyRoomsBiz` 우선순위 보정 (`:1149-1155`)

`Number.isFinite(byRb?.rooms)` 만으로는 부족. **byRb 의 실유효성** 도 함께 봐야 함.

대안 A — 의미 있는 양수만 우선:
```js
const hasMeaningfulRb = (v) => Number.isFinite(v) && v > 0
const match = hasMeaningfulRb(byRb?.rooms)
  ? Number(byRb.rooms)
  : (Number.isFinite(legacyMatch) ? legacyMatch : 0)
```
- 단점: 정말로 0 이 맞는 경우 (방이 다 찼다거나) 도 legacy 로 빠짐

대안 B — rooms_biz 가 명시적 0 vs 미설정 구분:
```js
const hasField = (v) => v !== undefined && v !== null
const match = hasField(byRb?.rooms) && Number.isFinite(byRb.rooms)
  ? Number(byRb.rooms)
  : (Number.isFinite(legacyMatch) ? legacyMatch : 0)
```
- 단점: 위 시나리오에선 byRb.rooms 가 0 이라 hasField 통과 → 여전히 같은 결과

대안 C (권장) — **rooms_biz 의 "활성도" 신호** 로 판단:
```js
// pastedText / needRooms / needPeople 중 하나라도 있을 때만 rooms_biz 의 값을 신뢰
const isRbActive = !!(byRb && (byRb._hasPastedText || byRb._hasNeedFields))
const match = isRbActive && Number.isFinite(byRb?.rooms)
  ? Number(byRb.rooms)
  : (Number.isFinite(legacyMatch) ? legacyMatch : 0)
```
- `subscribeRoomsBiz` 가 `map[id]` 만들 때 `_hasPastedText` / `_hasNeedFields` 플래그 set
- 둘 다 없으면 byRb 자체가 의미 없다고 판단해 legacy 로 폴백

### 🟠 우선 2 — `subscribeRoomsBiz` 의 sequential await 병렬화 (`:1363-1412`)

10초 지연 자체를 줄임. for-loop 안의 await 을 `Promise.all` 로 변경:
```js
const results = await Promise.all(entries.map(async ({ id, x }) => {
  let pastedText = String(x.lastPastedText || x.manualText || x.bannerText || '').trim()
  if (!pastedText) {
    try {
      const bizId = ...
      pastedText = (await fetchLatestMessageText(bizId)).trim()
    } catch {}
  }
  // ... 계산 ...
  return [id, { rooms, people, ... }]
}))
const map = Object.fromEntries(results)
```
- 50개 doc 동시 처리 → 전체 시간 ~50ms × 5 = ~250ms (또는 가장 느린 doc 처리 시간)
- **이걸로 10초 지연 → 1초 미만**. 우선 1 까지 적용하면 0/0 깜빡임 자체가 안 보임
