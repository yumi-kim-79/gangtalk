### 1-2. 스크롤 컨테이너 CSS 비교

### 1-3. 카드 CSS 비교 (★ 결정적 차이)

**제휴관 `.rs-card` (`PartnersPage.vue:1802-1815`)**:
```css
.rs-card{
  flex: 0 0 auto;                     /* ← ★ flex-grow:0, flex-shrink:0, flex-basis:auto */
  width: calc((100% - (var(--gap) * (var(--cards-per-view) - 1))) / var(--cards-per-view));
  min-width: 220px;
  ...
}
```
- **`flex: 0 0 auto` = flex-shrink 0** → **컨테이너 폭 안으로 축소 안 함**
- `width: calc(...)` 로 명시 폭 지정 (또는 `min-width: 220px` 우세)
- 결과: 카드 5 × 220 + gap = 1140 > 화면 → **컨테이너 넘어감 → overflow:auto 발동 → 스크롤 정상** ✓

**가게찾기 `.mini` (`StoreFinder.vue:2268-2273`)**:
```css
.mini{
  appearance: none;
  min-width: 160px;                    /* ← min-width 만 */
  text-align: left;
  border: 1px solid var(--line);
  ...
  /* flex 명시 없음 → default: flex: 0 1 auto (grow:0, shrink:1, basis:auto) */
}
```
+ `.sf-tops :deep(.mini) { min-width: var(--card-min-width, 180px); }` (오버라이드, `:1994-2001`)

- **flex-shrink default = 1** → **컨테이너 폭 안으로 축소 가능**
- flex 컨테이너 (`.top-row`) 가 화면 폭 380 정도
- 자식 5 × 180 요구 폭 = 900 → 컨테이너 폭 초과
- **`flex-shrink: 1` 이면 브라우저가 자식 폭을 강제 축소 시도**
  - min-width 180 이 하한선이라 이론상 안 줄어들어야 하지만, min-width 는 "최소" 보장만 함 (스펙상)
  - **일부 브라우저는 flex-shrink:1 + min-width 조합에서도 자식 폭을 컨테이너에 맞춰 재분배**
- 결과: **화면에 2개만 fit, 나머지는 컨테이너 밖으로 밀리지 않고 flex 재계산으로 사라짐 or 축소** → 스크롤 조건 미충족

### 2-6. `.gt-slider-bar { aspect-ratio }` 자식 상속 문제

**CSS Spec (draft)**:
- `aspect-ratio` 는 "used size" 를 계산해 element 의 height 를 만듦
- 자식이 `height: 100%` 로 percentage 상속하려면 부모가 **"definite height"** 를 가져야 함
- **aspect-ratio 로 만든 height 가 definite 인가?**
  - **Chrome/Edge 최신**: definite 로 취급 → 자식 percentage 상속 OK
  - **Firefox 최신**: definite 로 취급 → OK
  - **iOS Safari 15 미만, 옛 안드로이드 Chrome**: **indefinite 로 취급 → 자식 percentage 상속 실패 → height=0**

**증상**:
- 부모 `.gt-slider-bar` 는 aspect-ratio 로 시각적 height 있음 (배경 회색 표시)
- 자식 `.gt-slide` height=0 → 이미지 안 보임 (사용자 눈에는 슬라이드가 안 넘어가는 것으로 인식)
- 그러나 `sliderIdx` / `transform` 은 실제로 잘 작동 중

### 2-7. PR #118 이전 (height:180px 고정) 은 왜 됐나
```css
/* PR #118 이전 */
.gt-slider-bar { height: 180px; }         /* definite */
.gt-slider-track { height: 100%; }          /* 부모 definite → percentage 상속 OK */
.gt-slide { height: 100%; }                 /* 상속 OK */
```
- 부모가 명시적 `height: 180px` → definite → 모든 브라우저 percentage 상속 정상
- PR #118 이 `height: 180px → aspect-ratio` 바꾸며 **명시적 height 를 aspect-ratio 계산 height 로 교체** → 브라우저별 편차 발생

### 2-8. aspect-ratio 유지하며 가로 이동 살리는 방법

**옵션 A — 자식에게 자체 aspect-ratio 부여 (권장, 최소 변경)**:
```css
.gt-slide {
  flex: 0 0 100%;
  width: 100%;
  aspect-ratio: var(--gt-slider-aspect, 12 / 5);   /* ← ★ 추가 */
  /* height: 100% 제거 */

```
- 자식이 **자체** aspect-ratio 로 height 계산 → percentage 상속 불필요
- 부모 `.gt-slider-bar` aspect-ratio 는 유지 (뷰포트 크기 확정)
- `.gt-slide-img { height: 100% }` 는 부모 `.gt-slide` 가 자체 aspect-ratio 로 definite height → 상속 OK
- **PR #118 효과 (이미지 잘림 0) 유지**
- 변경 최소 (`.gt-slide` 에 1줄 추가, `height: 100%` 제거)

**옵션 B — 자식 height 를 명시적 fallback**:
```css
.gt-slider-bar { aspect-ratio: 12/5; min-height: 140px; }   /* PR #127 방식 */
.gt-slider-track { height: 100%; }
.gt-slide { height: 100%; }
```
- 부모 `min-height` 로 definite fallback 제공
- PR #127 이 시도했으나 실패했다고 판단됨 (PR #127 은 `.gt-slider-track` 을 `position:absolute; inset:0` 로 바꾼 게 진짜 문제였음. min-height 자체는 무해)
- 다시 시도 가능하지만 옵션 A 가 더 clean

**옵션 C — 부모 대신 track 이 aspect-ratio**:
```css
.gt-slider-bar { /* aspect-ratio 제거 */ position: relative; overflow: hidden; ... }
.gt-slider-track { display: flex; width: 100%; aspect-ratio: 12/5; ... }
.gt-slide { flex: 0 0 100%; width: 100%; height: 100%; }
```
- track 이 자체 aspect-ratio → definite height → 자식 percentage 상속 OK
- 부모 `.gt-slider-bar` 는 자식 크기 따라감
- 변경 폭 좀 큼

## 3. PR #127/#128 왜 실패했나 (재분석)

### 3-1. PR #127 이 잘못 겨눈 곳

- Top5 스크롤과 무관한 카드 썸네일에 손을 대 원치 않는 영향 가능

### 3-2. PR #128 이 잘못 겨눈 곳
- **`display: flex !important; flex-wrap: nowrap !important; overflow-x: auto !important`** 를 컨테이너 (`.top-row / .rs-scroller`) 에 강제
- 그러나 원래 컨테이너는 이미 `display: flex; overflow: auto` 정상 상태 → 이 강제는 **아무것도 안 함**
- 진짜 원인은 **자식 flex-shrink** — PR #128 은 자식을 안 건드림

### 3-3. PR #129 (revert) 로 두 PR 무효화한 게 옳음
- 다만 revert 만으로는 **원래 있던 진짜 문제 (자식 shrink, 자식 height 상속) 미해결**
