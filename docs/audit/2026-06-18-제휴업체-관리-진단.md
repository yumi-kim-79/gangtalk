# 관리자 빌드 제휴업체(partners) 관리 페이지 — 사전 진단

**날짜**: 2026-06-18
**범위**: gangtalk815 관리자 빌드. partners 컬렉션 CRUD 페이지 신규 작성 전 사전 진단
**전제**: 진단 전용. 코드/룰 수정·PR·배포 없음.
**핵심 결론**:
1. **partners 가 source**, `config/marketing.partnerCards*` 는 사본/인덱스 (3중 저장 패턴)
2. **회원 사이트의 AdminTools (마이페이지 내) 에 이미 CRUD 흐름이 존재** — 옛 관리 도구. 관리자 빌드로 이전하면서 재활용 가능
3. **firestore.rules + storage.rules 모두 관리자 CRUD 허용 — 신규 룰 변경 0건**
4. **이미지 경로**: `marketing/partnerCards/{id}/img-{i}-{ts}.jpg` 또는 `thumb-{ts}.jpg`
5. **`partnerRequests` 와 별개**: 외부 사용자가 제휴 신청하는 경로, 승인 시 partners 로 이전 (별도 흐름)
6. 신규 페이지 위치: `/admin/partners` 신설. `StoresManagePage` 패턴 재활용

### 1-2. 사용자 화면이 노출하는 조건 (`PartnersPage.vue:696-714 isPartnerApproved`)
```js
function isPartnerApproved(x) {
  const active = (x.active !== false)
  const approvedFlag = x.approved === true
  const apply = String(x.applyStatus || '').toLowerCase()
  const applyApproved = ['approved','승인','승인완료'].includes(apply)
  // 명시적 승인 정보가 없으면 active 만으로 노출
  if (typeof x.approved === 'boolean' /* or apply 명시 */) return active && (approvedFlag || applyApproved)
  return active
}
```
→ 관리자 페이지에서 `active` / `approved` / `applyStatus` 토글로 노출 제어

## 2. partners vs config/marketing.partnerCards — source 관계

### 2-1. 3중 저장 패턴 (`useMyPageCore.js:944-994 savePartnerOne`)

신규/수정 시:
1. **`partners/{id}` 컬렉션** (source) — 전체 필드 저장 (`:966-972`)
2. **`config/marketing/partnerCards/{id}` 서브컬렉션** (사본, 일부 필드만) — `name/region/category/thumb/images/desc/...` (`:974-980`)
3. **`config/marketing.partnerCardIndex` / `.partnerCards` / `.partnerCardList`** (배열 인덱스, 가벼운 필드만) — `id/name/region/category/thumb/adStart/adEnd/rating` (`:987-994`)

### 2-2. 사용자 화면이 읽는 순서

| 화면 | 1순위 | 2순위 폴백 |
|---|---|---|
| `PartnersPage.vue:763` | `partners` 컬렉션 | (이미지만 partnerRequests 폴백) |
| `PartnerDetail.vue:339-343` | `partners/{id}` | `config/marketing.partnerCards` 배열 |
| `FavoritesPage.vue:297-301` | `partners/{id}` | `config/marketing.partnerCards` 배열 |
| `useMyPageCore.js:1424,1462` | `partnerCards` 서브컬렉션 + `partners` 둘 다 | — |

→ **`partners` 가 single source of truth**. `partnerCards` 시리즈는 빠른 조회 / 호환성 폴백 / 옛 데이터 호환

### 2-3. 신규 관리 페이지의 저장 정책 권장

기존 3중 저장 패턴 유지 — 모든 사용자 화면 호환성 보장. `savePartnerOne` 로직 재활용 또는 거의 그대로 이전.

## 5. `partnerRequests` 관계 — 별도 흐름

### 5-1. 흐름
- 외부 사용자 (제휴 신청자) 가 `partnerRequests/{reqId}` 에 신청 (`signedIn` + `ownerId==auth.uid` + `status='pending'`)
- 관리자가 검토 후 승인 시 → 별도 `partners/{id}` 로 이전 (현재 미구현 or 수동)
