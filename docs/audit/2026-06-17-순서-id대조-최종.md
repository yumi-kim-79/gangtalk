# 순서 어긋남 — homeOrder ID 1:1 대조 최종 진단

**날짜**: 2026-06-17
**범위**: gangtox.com 현황판 "강남 인기 업소" vs gangtalk815.com /admin/stores "노출 업소 관리"
**전제**: 지표 덮어쓰기는 PR #71 로 해결됨. 코드 정렬 로직·저장·배포·권한 모두 정상. 본 진단은 "순서 어긋남" 단일 주제.
**결론**: **코드 버그 아님 (수정 없음)**. 사용자/관리자 화면이 같은 stores 컬렉션을 보지만 **사용자만 적용하는 필터 2개** (광고 기간 + 노출 토글) 가 homeOrder 의 일부 ID 를 base 에서 제외 → 자리가 비면서 updatedAt desc 폴백이 채워져 "거의 안 겹쳐 보임" 으로 나타난 것.

## 4. "유앤미 / 엘리트 / 퍼펙트 / 드라마" 가 사용자 상위에 오는 이유 (가설)

사용자가 보고한 단서:
- 관리자 상위: **레이블, 달토, 유앤미, 도파민** ...
- 사용자 상위: **유앤미, 엘리트, 퍼펙트, 드라마** ...
- "거의 안 겹침" — 유앤미 1개만 공통

코드 흐름으로 추정되는 시나리오:
1. **관리자 homeOrder 19개 중 사용자 base 통과 가게가 ~1-2개 (유앤미 포함)** 일 가능성 높음
2. 나머지 17-18개는 다음 중 하나로 사용자 base 에서 빠짐:
   - **`exposure.gangtalk === false`** (관리자가 노출관리에서 토글 OFF 한 가게) — 가장 가능성 높음
   - **`adStart/adEnd` 만료** (관리자가 노출 기간 설정 후 만료)
   - `hidden === true`
3. 빠진 자리 17-18 칸을 base 의 나머지 가게 (homeOrder 에 없음 → Infinity) 가 **`updatedAt desc`** 순서로 채움 → 엘리트/퍼펙트/드라마가 상위에 보임
4. 유앤미만 homeOrder 에 있고 base 도 통과 → 사용자 화면 상위에 유지됨

**즉 19개 homeOrder 가 거의 모두 노출 OFF / 광고 만료 상태일 가능성이 큼** — 그렇다면 사용자 화면은 사실상 homeOrder 무시 상태로 보임.

## 5. 런타임 확인 액션 (사용자가 콘솔에서 직접)

코드 분석으로는 여기까지가 한계. **결정적 사실 확정** 을 위해 사용자가 gangtox.com/dashboard 의 브라우저 콘솔에서 실행:

```js
// 1) homeOrder 19개 가져오기
firebase.firestore().doc('config/marketing').get().then(d => {
  const ho = d.data().homeOrder || []
  console.log('homeOrder count:', ho.length)
  console.log('homeOrder IDs:', ho.slice(0, 19))

  // 2) 각 ID 가 stores 컬렉션에 있는지 + exposure/applyStatus/adStart/adEnd 확인
  Promise.all(ho.slice(0, 19).map(id =>
    firebase.firestore().doc('stores/'+id).get()
      .then(s => ({
        id,
        exists: s.exists,
        name: s.data()?.name,
        exposure: s.data()?.exposure?.gangtalk,
        applyStatus: s.data()?.applyStatus,
        approved: s.data()?.approved,
        hidden: s.data()?.hidden,
        adStart: s.data()?.adStart,
        adEnd: s.data()?.adEnd,
        adActive: (!s.data()?.adStart && !s.data()?.adEnd) ||
                  (Date.now() >= (s.data()?.adStart || 0) && Date.now() < (s.data()?.adEnd || Infinity))
      }))
  )).then(rows => {
    console.table(rows)
    // exists=false → 컬렉션에 없음 (옛 ID)
    // exposure=false → 사용자 화면에서 빠짐
    // adActive=false → 사용자 화면에서 빠짐
  })
})
```

결과 해석:
- `exists: false` 가 다수 → **homeOrder 에 옛/삭제된 ID 누적**. 관리자 화면이 `limit(500)` 으로 보는 stores 의 일부만 homeOrder 에 있을 수 있음. (단, 관리자 화면도 같은 ID 로 매칭하므로 양쪽 다 무시됨 → 어긋남 원인 아님)
- `exposure: false` 다수 → **노출 토글 OFF 가게가 homeOrder 상위에 다수**. 사용자에서 자동으로 빠짐. **이게 가장 유력한 원인**.
- `adActive: false` 다수 → 광고 기간 설정 후 만료. 사용자에서 자동 빠짐.

## 6. 결론

### 6-1. 진짜 버그 vs 정상 동작
- **사용자 정렬 코드는 정상**. `homeOrder` 정상 로드, 정렬 로직 정상.
- **사용자/관리자 base 필터 차이가 곧 시각적 어긋남**:
  - 사용자만 `exposure.gangtalk===false` 제외 → 관리자 노출관리는 토글 OFF 도 보여줘야 하므로 이 차이는 의도된 것
  - 사용자만 `isActiveAd` 적용 → 광고 만료 가게는 노출 안 함이 정책
  - 사용자만 `hidden` 제외 → 의도된 것

### 6-2. 수정 여부
- **코드 변경 없음**. 두 화면의 표시 가게 집합이 다른 것이 정상.
- 사용자가 보고한 "거의 안 겹침" 은 **homeOrder 19개의 대부분이 사용자 base 필터에서 제외** 됐기 때문일 가능성이 높음. 코드의 책임이 아니라 **데이터 상태의 문제** (노출 토글 OFF / 광고 만료).

### 6-3. 운영 액션 제안 (코드 변경 없이)
관리자에게 보고 후 선택:
- **선택지 A — homeOrder 만 사용자에게 100% 반영하고 싶다**: gangtalk815.com /admin/stores → 노출 토글이 ON 인 가게만 homeOrder 에 올리고, 광고 기간을 무기한(미설정) 으로 두면 사용자 화면과 1:1 일치
- **선택지 B — 토글 OFF / 광고 만료 가게가 homeOrder 상위에 있어도 OK**: 현 상태 그대로 — 자동으로 사용자에서 빠지고 다른 가게가 채워짐
- **선택지 C — 코드 동작 변경 (필요한 경우 별도 PR)**: 사용자 화면에서도 `exposure.gangtalk===false` 가게는 homeOrder 상위면 표시하도록 정책 변경 — 단 이는 노출관리 토글의 의미를 뒤집는 것이라 비추천
