**StoreDetail 의 별점 패턴과 100% 동일** — `runTransaction` + 본 doc 의 4 필드 갱신 + 서브컬렉션 `ratings/{uid}` 본인 doc set/delete.

### 1-2. 차단 위치

**차단 (1) — `partners/{id}/ratings/{uid}` 서브컬렉션 룰 부재**

```
# firestore.rules 전체 검색 결과:
match /stores/{storeId}/ratings/{uid}    → 있음 (:141-145)
match /partners/{partnerId}/ratings/{uid} → 없음
```

→ Firestore default deny → `tx.set(myRef, {...})` / `tx.delete(myRef)` 모두 거부

**차단 (2) — `partners/{id}` update 가 admin only**

`firestore.rules:238`:
```
match /partners/{id} { allow read: if true; allow write: if isAdmin(); }
```

→ `tx.update(partnerRef, { ratingSum, ratingCount, rating, updatedAt })` 가 비-관리자 사용자에게 거부

**결과**:
- `runTransaction` 안에서 둘 중 하나라도 룰 거부되면 트랜잭션 전체 throw
- catch (`PartnerDetail.vue:296-300`) 진입 → `myRating.value = prevMy` 롤백 → 화면 변화 없음
- 콘솔에 `FirebaseError: Missing or insufficient permissions` 표시

### 1-3. stores (PR #74 정상 동작) 와 비교

`firestore.rules:108-133` (stores) — update 분기에 별점 화이트리스트:
```
allow update: if signedIn() && (
  isAdmin()
  || ( 본인 owner 분기 )
  || changesAreOnly(['rating', 'ratingSum', 'ratingCount', 'updatedAt'])   ← 핵심
)
```

`firestore.rules:141-145` (stores ratings):
```
match /stores/{storeId}/ratings/{uid} {
  allow read: if true;
  allow create, update, delete: if isOwner(uid) || isAdmin();
}
```

partners 룰에는 둘 다 부재.

## 5. 고칠 방향 — 룰만 추가 (코드 0)

### 5-1. `firestore.rules:238` partners 룰 확장 (stores `:108-133` 패턴)

현재:
```
match /partners/{id}  { allow read: if true;  allow write: if isAdmin(); }
```

변경 후 (예시):
```
match /partners/{id} {
  allow read: if true;

  // 관리자 외 일반 사용자는 별점/좋아요 4 필드만 갱신 가능 (위장 차단)
  allow create, delete: if isAdmin();
  allow update: if isAdmin()
                || (signedIn()
                    && changesAreOnly(['rating', 'ratingSum', 'ratingCount', 'likes', 'updatedAt']));
}
```

`changesAreOnly` 헬퍼는 `firestore.rules:26-28` 에 이미 정의됨 (재사용).

### 5-2. `firestore.rules` 에 partners 별점 서브컬렉션 매치 신규

`stores/{storeId}/ratings/{uid}` (`:141-145`) 와 동일 패턴:
```
match /partners/{partnerId}/ratings/{uid} {
  allow read: if true;
  allow create, update, delete: if isOwner(uid) || isAdmin();
}
```

### 5-3. 적용 후 효과

**별점**:
- `tx.set(partners/{id}/ratings/{uid}, { score, updatedAt })` ← `isOwner(uid)` 통과
- `tx.update(partners/{id}, { ratingSum, ratingCount, rating, updatedAt })` ← `changesAreOnly` 통과
- runTransaction 정상 commit → 별점 UI 정상 반영

**즐겨찾기**:
- `setDoc(favorites/{favId})` — 이미 통과
- `updateDoc(partners/{id}, { likes: increment(±1), updatedAt })` ← `changesAreOnly` 통과
- 찜 카운트 정상 증감

**관리자**:
- `isAdmin()` 분기 그대로 작동 — 관리자 페이지 (PartnersManagePage) 의 부동 필드 갱신 (name/region/category 등) 모두 통과

### 5-4. 보안 검증

- `changesAreOnly(['rating', 'ratingSum', 'ratingCount', 'likes', 'updatedAt'])` — 5 필드 외 변조 (name/region/thumb/category/active/approved/adStart/adEnd 등) 차단
- 본인 별점 doc 만 본인이 set/delete — 타인 별점 위변조 불가
- favorites 룰 그대로 — `type='partner'` 든 `type='store'` 든 본인 doc 만

### 5-5. 코드 변경 0

- `PartnerDetail.vue` — 그대로 작동
- `PartnersPage.vue` — 그대로 작동 (이벤트 리스너 + 로컬 폴백 모두 유지)
