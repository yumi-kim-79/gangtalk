## 4. 입력 → 저장 → 현황판 반영 흐름

### 4-1. BizMetricsPage.onSave (`:282-324`)

```js
async function onSave() {
  const match      = Number(form.value.match || 0)      // 5
  const persons    = Number(form.value.persons || 0)    // 8
  const totalRooms = Number(form.value.totalRooms || 0) // 0 (선택)
  ...
  const batch = writeBatch(fbDb)
  batch.update(doc(fbDb, 'stores', s.id), {
    match: 5, persons: 8, totalRooms, statusMode, status, updatedAt
  })
  batch.set(doc(fbDb, 'rooms_biz', s.id), {
    needRooms: 5,           // ← MainPage 가 읽는 필드
    needPeople: 8,          // ← MainPage 가 읽는 필드
    need: 8,
    totalNeeded: 8,
    totalRooms,
    manualSaved: true,      // ← MainPage 의 _manualSaved 통과
    manualSavedAt: now,
    updatedAt: now,
  }, { merge: true })
  await batch.commit()
}
```

### 4-2. 저장되는 doc ID — `s.id` 그대로 (sanitize 없음)

| 시나리오 | rooms_biz doc ID |
|---|---|
| stores 본 doc 의 id 가 `youandme` (사람이 읽는 키) | `rooms_biz/youandme` |
| stores 본 doc 의 id 가 `6uZOAi...` (auto-id, 대문자 포함) | `rooms_biz/6uZOAi...` |
| stores 본 doc 의 id 가 `pt_xxx_xxx` | `rooms_biz/pt_xxx_xxx` |

**BizMetricsPage 는 sanitize 안 함** (`:305`):
```js
batch.set(doc(fbDb, 'rooms_biz', s.id), {...})
```

→ **stores 본 doc 의 id 와 동일한 ID 로 rooms_biz 갱신**.

### 4-3. 대소문자 중복 doc 와의 관계 (진단 §4 참조)

- `BizMetricsPage` 는 stores 본 doc 의 id 그대로 사용 → **일관성 유지**
- ChatBiz 가 별도 sanitize 한 doc (예: `6uzoai...`) 에 저장한 옛 데이터가 있을 수 있음 — 이 doc 는 BizMetricsPage 가 안 건드림
- MainPage 의 `applyRoomsBiz` 가 `rooms_biz/{id}` 에서 stores.id 와 매칭 → **BizMetricsPage 저장 doc 와 일치**
- → BizMetricsPage 로 저장하면 **현황판이 정확히 그 값을 읽음** ✓

### 4-4. 사용자 화면 반영

MainPage 의 `subscribeRoomsBiz` onSnapshot 이 실시간 구독 → BizMetricsPage 저장 즉시 `rooms_biz/youandme` 변화 감지 → `applyRoomsBiz` 호출 → `stores.value` 갱신 → DOM 반영

→ **새로고침 없이 즉시 반영** (정상 작동 시)

## 6. 추가 케이스 — 대문자 doc 잔존 처리

### 6-1. 만약 stores 본 doc 의 id 가 `6uZOAi...` (대문자) 라면

BizMetricsPage 가 `rooms_biz/6uZOAi...` 에 저장.

### 6-2. 만약 stores 본 doc 의 id 가 소문자 (`youandme`) 인데 `rooms_biz/6uZOAi...` 같은 대문자 doc 가 있다면

- BizMetricsPage 는 `rooms_biz/youandme` 에 저장 → 현황판 정상 반영
- `rooms_biz/6uZOAi...` 는 잔존 (외부 시트 시스템이 갱신했을 가능성) — MainPage 는 무시
- 그러나 매핑 로직 (`MainPage.subscribeRoomsBiz:1431-1456`) 이 byName/byVendor 폴백으로 잘못된 매핑 가능 → **`_AMBIGUOUS` 차단** (PR #71)

### 6-3. 안전한 정정 (사용자 수동)

1. 먼저 BizMetricsPage 로 양수 저장 → stores.id 와 같은 doc 갱신 (정상)
2. 사용자 화면 반영 확인
3. **잔존 대소문자 doc 는 그대로 두기** (외부 시트 시스템 영향 가능성 — 진단 §5-1 절대 삭제 금지 원칙)
