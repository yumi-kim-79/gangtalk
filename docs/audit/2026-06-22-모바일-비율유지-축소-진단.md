# 모바일 위쪽 영역 — 비율 유지 축소 진단

날짜: 2026-06-22
선행 진단: `docs/audit/2026-06-22-모바일-UI밀도-조정-진단.md`
배경: 앞 진단은 height 고정값을 줄였음 (180→140). 사용자 지적 — height 만 깎으면
`object-fit: cover` 가 배너 이미지를 잘라냄. **비율 유지하면서 전체 축소** 가 정답.
범위: 진단 전용. 코드 / CSS / PR / 배포 변경 0건.

## 0. TL;DR

- **배너 현재 구조**: `height:180px` 고정 + `object-fit: cover` → height 줄이면 **이미지 상하 잘림**
- **베이스 `.banner-img`** (StoreFinder:2155) 는 원래 `height:auto; object-fit:contain` (비율 유지 디폴트) → 그러나 `.sf-banners :deep` 가 강제로 덮어씀
- **정석 해결책**: `height:180px` 제거 → `aspect-ratio: 12 / 5` (또는 마케팅 자료 실제 비율) 부여 → 폭 따라 height 자동 비율 계산, 잘림 0
- **카드 thumb** 는 이미 비율 패턴 보유 (`.m-thumb padding-top:54%` + `.rs-thumb background-size:contain`). 단 Top5 scope (`sf-tops :deep / pp-top-sec`) 가 `height:140px !important` 로 덮어쓰는 게 문제
- **`transform: scale()` 통짜 축소**: 권장 안 함. 부모 박스 크기는 그대로 → 빈 공간, 터치 영역 시각적 축소, subpixel 폰트 흐림, 이벤트 좌표 매핑 복잡, transform-origin/will-change 등 추가 부담
- **권장**: aspect-ratio 토큰 도입 (`--banner-aspect / --card-thumb-aspect`) + 폭/사이즈 토큰 별도 (`--card-min-width / --cat-icon-size`) → 한 곳에서 일관 조정

## 2. 비율 유지 축소 — 4 가지 방법 비교

### 방법 A — `aspect-ratio` (권장, 현대 CSS)
```css
.sf-banners :deep(.banner-img),
.pp-banners .banner-img,
.gt-slider-bar {
  width: 100%;
  height: auto;
  aspect-ratio: 12 / 5;   /* 또는 16/9 (1.78) / 2/1 / 마케팅 실제 비율 */
  object-fit: cover;       /* 또는 contain (4 참조) */
  display: block;
}
```

**효과**:
- 폭 100% × 비율 = 자동 height (예: 412 × (5/12) = 171.7px)
- 폭이 줄어들면 height 도 비율 따라 자동 축소 → 잘림 발생 0
- 컨테이너 좌우 padding 늘리면 폭이 줄어 → 자동으로 더 작아짐

**장점**:
- 단순, 선언적, 1 줄
- 폭 조정만으로 전체 크기 자유롭게 조절
- 토큰화 가능 (`var(--banner-aspect)`)
- iOS Safari 15+ / Android Chrome 88+ 모두 지원 (모바일 대응 충분)

**단점**:
- 마케팅 자료의 실제 비율과 toler 비율 ≠ 일 때 미세 잘림 (cover) 또는 빈 공간 (contain) 발생
- → 마케팅 자료의 표준 비율 확정 필요 (예: "모든 배너는 12:5 비율로 제작")

### 방법 B — `padding-top` 트릭 (구형, 더 호환성 좋음)
```css
.banner-wrap{
  position: relative;
  width: 100%;
  padding-top: 41.67%;    /* = 5/12 비율 = aspect-ratio 12/5 */
}
.banner-wrap > .banner-img{
  position: absolute; inset: 0;
  width: 100%; height: 100%;
  object-fit: cover;
}
```

**장점**:
- IE11 / 옛 Safari 까지 지원
- 현재 `.m-thumb { padding-top: 54% }` (StoreFinder:2238) 가 이미 이 패턴 사용

**단점**:
- 마크업 wrapper 1 단계 추가
- 비율 계산 직관적이지 않음 (5/12 = 41.67%)
- aspect-ratio 보다 verbose

### 방법 C — 컨테이너 폭 축소 (= 더 작게)
```css
.sf-banners,
.pp-banners {
  max-width: 92%;
  margin: 0 auto;
}
```

**장점**:
- 방법 A 와 결합 시 — 폭이 줄어 height 자동 축소 → 비율 유지 + 전체 작아짐
- 페이지 좌우 여백 강조

**단점**:
- 좌우 빈 공간 (디자인 의도 확인 필요)

### 방법 D — `object-fit: contain` (이미지 잘림 0)
```css
.banner-img {
  width: 100%;
  height: 180px;        /* 또는 aspect-ratio */
  object-fit: contain;  /* cover → contain */
}
```

**장점**:
- 원본 비율 100% 보존 → 잘림 절대 0

**단점**:
- 컨테이너와 이미지 비율 다르면 **상하 또는 좌우 빈 공간** ("레터박스")
- 예: 컨테이너 412×180 (2.29:1) + 이미지 1080×400 (2.7:1) → 상하 약 18px씩 빈 공간
- 빈 공간 배경색 (`background:#f0f0f0` 등) 처리 필요
- 디자인적으로 어색해질 수 있음
- 권장: **마케팅 자료 비율과 컨테이너 비율이 다를 때만 사용**

### 결론 — 사용자 의도에 가장 가까운 방법
| 사용자 요구 | 권장 방법 |
|---|---|
| 이미지 안 잘림 + 전체 작아지기 | **A (aspect-ratio)** + 마케팅 자료 비율 고정 |
| 이미지 비율 자유 + 잘림 0 | D (contain) — 단 빈 공간 허용 |
| 더 작게 하면서 안전 | A + C 결합 (aspect-ratio + max-width 축소) |

## 3. `transform: scale()` 통짜 축소 — 권장 안 하는 이유

```css
.sf-banners,
.mp-cat,
.sf-tops {
  transform: scale(0.85);
  transform-origin: top left;
}
```

### 부작용
1. **부모 박스 크기는 그대로**:
   - scale 은 시각적 크기만 변경. layout 흐름의 박스 크기는 원본 (180px 유지)
   - 시각적 축소 (153px) + 박스 (180px) = **빈 27px 공백** 발생
   - 해결하려면 `width: 117.6%; transform: scale(0.85) translateX(...)` 등 복잡한 보정 필요

2. **터치 영역 시각적 작아짐**:
   - 버튼/링크가 화면에서 작아 보임 → WCAG 44px 최소 권장 위반 가능
   - 단 이벤트 hit area 자체는 원본 크기 유지 (혼란 유발)

3. **자식 텍스트 subpixel 렌더링 흐림**:
   - 폰트가 0.85배 스케일 → 13px → 11.05px → 브라우저가 반올림하며 가독성 저하
   - 줄간격/letter-spacing 도 비례 흐림

4. **이벤트 좌표 매핑 복잡**:
   - drag/drop, hover, click 의 시각 위치 vs 이벤트 좌표 불일치
   - SortableJS (배너/카테고리 드래그) 와 충돌 가능성

5. **z-index / overflow 부작용**:
   - scale 적용된 요소 위 absolute 자식의 위치 계산 어긋남
   - sticky / fixed 자식 무력화

6. **transition / animation 부담**:
   - GPU 가속 (`will-change: transform`) 필요 → 메모리 ↑

### 권장 대안
**개별 요소를 토큰 기반으로 비율 유지 축소**:
- 배너: aspect-ratio 토큰
- 카드: min-width 토큰 + padding-top 비율 또는 aspect-ratio
- 카테고리: 원형 size 토큰 (이미 비율 고정)
- 폰트/패딩: 별도 토큰

→ 레이아웃 정확, 폰트 또렷, 터치 영역 정상.

## 4. 카드 (Top5 / 인기업소) 비율 유지 축소

### 4-1. 가게찾기 Top5 `.m-thumb`
**베이스** (`StoreFinder.vue:2238`):
```css
.m-thumb{
  position:relative;
  width:100%;
  padding-top:54%;     /* ← 비율 유지 (방법 B) */
  background-size:cover;
}
```

**sf-tops scope 덮어쓰기** (`:1990-1993`):
```css
.sf-tops :deep(.m-thumb){
  padding-top:0 !important;    /* ← 비율 패턴 무력화 */
  height:140px !important;     /* ← 고정값 */
}
```

→ Top5 에서는 고정 140px 로 강제. **베이스 비율 패턴 무력화**.

### 4-2. 제휴관 Top5 `.rs-thumb`
**베이스** (`PartnersPage.vue:1801`):
```css
.rs-thumb{
  width:100%; height: 120px;
  background-size: contain;    /* ← contain (잘림 0) */
}
```

**pp-top-sec scope** (`:1457-1460`):
```css
.pp-top-sec .rs-thumb{
  height:140px !important;
  padding-top:0 !important;
}
```

→ contain 유지하므로 안 잘리지만 빈 공간 가능.

### 4-3. 현황판 mp-store-img — `MainPage.vue:2647-2657`
```css
.mp-store-img{
  width:96px; height:96px;     /* 정사각 — 비율 1:1 */
  background-size:cover;       /* 잘림 가능 (1:1 비율 외 이미지) */
}
```
→ 정사각이라 비율은 자동 유지 (1:1). 다만 background-size: cover 라 1:1 아닌 사진은 잘림 (현황판 thumbVer 정책 — 업체가 직접 정사각 업로드 권장)

### 4-4. 카드 비율 유지 축소 권장
**가게찾기 Top5**:
```css
.sf-tops :deep(.mini){
  min-width: var(--card-min-width, 180px);   /* 200→180 폭 축소 */
}
.sf-tops :deep(.m-thumb){
  /* height:140px !important 제거 */
  width: 100%;
  aspect-ratio: var(--card-thumb-aspect, 16 / 9);
  height: auto !important;
  padding-top: 0 !important;
}
```
- 카드 폭 200→180 → m-thumb 폭 자동 180 → height = 180 × 9/16 = 101px (현재 140 → 101, -39px)
- 비율 유지 → 이미지 안 잘림 (cover 라도 16:9 비율 사진이면 정확히 채움)

**제휴관 Top5** — 같은 패턴 (rs-thumb 도 aspect-ratio 적용)

**현황판 mp-store** — 정사각 유지:
```css
.mp-store-img {
  width: var(--store-thumb-size, 80px);   /* 96→80 */
  height: var(--store-thumb-size, 80px);
}
```
- 1:1 비율 자동 유지

## 7. PR 단위 — 비율 유지 축소 안전 분할

### PR 2 — 배너 aspect-ratio 전환 (이미지 잘림 0 핵심) ★
- 파일: `StoreFinder.vue` (.sf-banners) + `PartnersPage.vue` (.pp-banners) + `GangTalkPage.vue` (.gt-slider-bar)

  - `height:180px / min-height:180px` 제거

- 권장 비율: 모바일 화면 비중 줄이려면 **2.4:1 ~ 3:1** (172px ~ 137px)
- 마케팅 자료 비율 미정이면 → PR 3 (object-fit: contain 옵션) 검토

- 배경색 (`background: #f0f0f0` 또는 회사 톤) 설정 필요
- 마케팅 자료 비율 통일이 어려운 경우만 채택

## 10. 결론

- **height 고정 + cover 가 잘림의 원인** — 모든 배너/슬라이더의 공통 패턴
- **정석은 aspect-ratio** — 현대 CSS 1 줄로 비율 유지 + 폭 따라 자동 축소
- **transform: scale() 권장 안 함** — 박스 크기, 폰트 흐림, 이벤트 좌표 등 6 가지 부작용
- **카드 thumb 도 aspect-ratio 패턴** — `height:140 !important` 덮어쓰기 제거 후 비율 적용
- **카테고리 원형은 이미 비율 고정** — size 토큰만 도입하면 끝
- **전역 토큰** — `--banner-aspect / --card-min-width / --cat-icon-size` 등 한 곳에서 일관 조정
- **사용자 액션 필수** — 마케팅 자료 비율 확정 (12/5 권장)
- **변경 0**: 본 문서는 진단만. 코드/CSS/PR/배포 없음
