## 0. TL;DR

- **증상 1 (배너 슬라이드 안 넘어감)** 은 대부분 **오해**:
  - **MainPage (현황판)**: 배너 자체가 **없음** — "핫이슈" 카드 (`mp-hot`) 만
  - **StoreFinder (가게찾기)**: `oneBanner = ...slice(-1)` — **최신 1장만 표시**. 슬라이드 로직 자체 없음. 인디케이터 3점은 **주석 명시 "1장이지만 시각 디자인 통일용" 정적 장식** (`StoreFinder.vue:108`)
  - **PartnersPage (제휴관)**: `bannersToShow = ...slice(0, 1)` — **첫 1장만**. 동일 패턴
  - **강톡 (GangTalkPage)** 만 실제 슬라이더 — `setInterval` 4초 + `transform: translateX(-${sliderIdx * 100}%)`. 여기서만 실제 이동 필요
- **증상 2 (가로 스크롤 안 됨)** 은 실제 문제 가능성 있음:
  - Top5: `overflow: auto` + `flex` + `min-width` 조건은 CSS 측 정상 → 다른 인터섭트 (드래그 이벤트 등) 의심
  - **카테고리는 원래 스크롤 아님** — PR #101/#102 로 grid 5×2 (한눈에 표시). 사용자 인식 오류
- **PR #118 aspect-ratio 전환 영향**:
  - 강톡 슬라이더 (`gt-slider-bar`) 에는 영향 가능성 있음 — 부모 `aspect-ratio` + 자식 `height: 100%` 조합은 iOS Safari 15 미만 등 오래된 브라우저에서 percentage 상속 실패 가능
  - StoreFinder/PartnersPage 배너는 그림 자체는 표시 정상 (aspect-ratio 도입) → 슬라이드는 애초에 없어서 무관
- **PR #120 카드 min-width 축소** 는 `.rs-scroller / .top-row` 의 `overflow: auto` 정책 유지 → 스크롤 조건 그대로 → PR #120 이 스크롤 깨진 원인은 아님

**핵심 위험 요소**:
- **부모 `aspect-ratio` + 자식 `height: 100%` 조합**
- CSS Spec: `aspect-ratio` 는 element 의 "computed height" 를 결정. 자식의 `height: 100%` 는 부모의 computed height 를 참조 → 이론상 작동
- **iOS Safari 15 미만 / 안드로이드 오래된 크롬** 등 일부 환경에서 `aspect-ratio` 계산 height 를 자식 percentage 상속에 사용 못 하는 케이스 알려져 있음
- 이 경우 `.gt-slide { height: 100% }` → 0px → 슬라이드 이미지 렌더 정상이지만 track 이동이 시각적으로 무의미해질 가능성

## 4. 각각 고칠 방향

### 4-1. 증상 1: 강톡 슬라이더 안 넘어감 (진짜 이슈)

**진단 확정 방법**:
- Chrome DevTools 에서 `.gt-slider-bar` computed height 확인
- `0px` 또는 이상 값이면 aspect-ratio 자식 상속 이슈 확정

**해결 방향 (원인 확정 후)**:
- **옵션 A**: `.gt-slider-bar` 에 명시적 height fallback:
  ```css
  .gt-slider-bar{
    aspect-ratio: var(--gt-slider-aspect, 12 / 5);
    min-height: 140px;         /* fallback for browsers with aspect-ratio bugs */
  }
  ```
- **옵션 B**: 자식 `.gt-slider-track / .gt-slide` 를 `position: absolute; inset: 0` 로 부모 채움
  ```css
  .gt-slider-bar{ position: relative; aspect-ratio: 12/5; }
  .gt-slider-track{ position: absolute; inset: 0; display: flex; ... }
  ```
  - `position: absolute + inset: 0` 은 percentage 상속 이슈 회피
- **옵션 C**: `aspect-ratio` 이전으로 되돌리기 (padding-top 트릭)
  ```css
  .gt-slider-bar{
    position: relative;
    padding-top: 41.67%;        /* = 5/12 */
    height: 0;
  }
  ```
  - 구형 호환 100%. 단 CSS 코드 길어짐

### 4-2. 증상 1 오해 해소 (배너 = 1장 표시 정상)
- 사용자에게 "StoreFinder/PartnersPage 는 원래 1장만 표시하는 설계 (`slice(1)`)" 안내
- 인디케이터 3점은 시각 장식 (`aria-hidden="true"`)
- 여러 장 슬라이드 원하면 → **별도 PR** 로 슬라이드 로직 구현 필요 (`sliderIdx` ref + `setInterval` + `transform` — 강톡 패턴 재사용)

### 4-3. 증상 2: Top5 가로 스크롤 안 됨

**진단 확정 방법**:
- DevTools 에서 `.top-row scrollWidth` vs `clientWidth` 비교
- `touch-action` computed 값 확인 (`auto` 여야 함, `none/pan-y` 면 문제)

**해결 방향 (원인별)**:
- **후보 D (드래그 이벤트 인터셉트)**:
  ```html
  <!-- StoreFinder.vue:216-234 -->
  <button
    class="mini click"
    @touchstart.passive="editMode ? noop() : tapStart"
    @touchmove.passive="editMode ? noop() : tapMove"
    ...
  >
  ```
  - `.passive` 이미 있음 → 브라우저 최적화 방해는 아님
  - **문제**: `@touchmove` 가 vertical + horizontal 구분 안 하고 tap 로직 실행 → iOS 에서 스크롤 우선 못 잡을 수 있음
  - 해결: `@touchmove` 로직에서 dx/dy 검사, |dx| > |dy| 이면 스크롤 전달 (`e.preventDefault` 안 함)

- **후보 F (touch-action)**: 상위 컨테이너에 `touch-action: pan-y` 가 있으면 가로 스크롤 막힘
  - `.page / .sf-tops / .top-row` 각각 `touch-action` 확인
  - 필요 시 `.top-row { touch-action: pan-x }` 명시

- **후보 B (부모 overflow-x: hidden)**:
  - `body / html / .page` 등에 `overflow-x: hidden` 있으면 자식 가로 스크롤 이벤트 시각화 못할 수 있음 (스크롤 자체는 됨)
  - 상위 검사 필요
